# 资产定义与主动提取机制

## 1. 什么是“资产”

在员工与机器人协作场景里，**资产**不是“任何被生成过的内容”，而是满足以下 5 个条件的可复用对象：

1. **可复用**
   - 能在多个任务、多个员工、多个机器人或多个组织单元中重复使用
2. **可封装**
   - 能被描述成一个边界清晰的最小单元，而不是散乱上下文
3. **可交付**
   - 能以产品化形式被保存、安装、配置、分发、升级、下架
4. **可治理**
   - 能被归属、审核、追踪、度量、回滚、退役
5. **可验证**
   - 能通过真实使用结果判断它是否有效、是否稳定、是否值得推广

如果一个对象只满足“生成过”，但不满足上面 5 条中的大部分，它就只是**内容**，不是**资产**。

---

## 2. 资产的一级类型

建议先把资产定义为 6 个一级类型。

### 2.1 `prompt`

定义：

- 一段可独立复用的提示策略，用于稳定地产出某类结果

典型形态：

- 分类提示词
- 摘要提示词
- 改写提示词
- 审核提示词

最小复用单元：

- 一段输入指令 + 约束 + 输出预期

### 2.2 `template`

定义：

- 面向固定业务场景的内容模版，通常带变量槽位

典型形态：

- 周报模版
- 客户回复模版
- 会议纪要模版
- 招聘邀约模版

最小复用单元：

- 模版正文 + 参数槽位 + 适用场景

### 2.3 `workflow`

定义：

- 为完成某类任务而形成的稳定步骤链路

典型形态：

- 先检索资料，再生成摘要，再发起审批
- 先识别客户意图，再查 CRM，再生成销售建议

最小复用单元：

- 步骤序列 + 依赖工具/知识 + 输入输出衔接

### 2.4 `knowledge`

定义：

- 被反复引用、可支撑机器人决策或生成内容的知识材料集合

典型形态：

- FAQ
- 制度文档集合
- 产品知识包
- 标准作业说明

最小复用单元：

- 知识条目集合 + 来源 + 适用范围 + 时效属性

### 2.5 `agent`

定义：

- 为某类目标任务而配置好的“职责明确、协作方式明确”的机器人角色

典型形态：

- 销售线索分析 Agent
- 招聘初筛 Agent
- 合同审阅 Agent

最小复用单元：

- 角色定位 + 目标任务 + 工作边界 + 协作方式 + 核心运行策略

### 2.6 `capability`

定义：

- 员工从业务角度感知到的“机器人会做什么”的复用能力，通常是对 prompt / workflow / knowledge / tool 组合的业务包装

典型形态：

- 自动生成客户跟进摘要
- 识别发票异常
- 整理面试评估意见

最小复用单元：

- 能力名称 + 价值描述 + 场景 + 运行载体

## 3. 资产识别的核心原则

系统不能靠“看到文本就提取”。识别资产必须基于以下原则。

### 3.1 稳定性原则

只有重复出现、结果稳定、边界清晰的对象，才值得成为资产候选。

### 3.2 价值性原则

只有能明显节省时间、提高质量、扩大复用面或降低风险的对象，才值得进入资产链路。

### 3.3 独立性原则

资产候选必须可以脱离当前单次会话，在相似任务中被再次使用。

### 3.4 可治理原则

资产候选必须能够找到来源、所有者、版本和适用范围，否则不能进入企业和平台流转。

## 4. 每类资产如何被识别发现

### 4.1 Prompt 资产的识别

识别信号：

1. 员工多次手工输入结构相似的高质量指令
2. 同类任务中某段提示策略反复带来高成功率结果
3. 员工手工微调后反复复用同一提示框架

判定标准：

1. 近 N 次任务中结构相似度高
2. 成功率明显高于基线
3. 不依赖过多一次性上下文

### 4.2 Template 资产的识别

识别信号：

1. 员工反复生成格式相近的文本结果
2. 文本主体稳定，仅少量字段变化
3. 结果经常被复制发送给外部对象

判定标准：

1. 输出结构高度一致
2. 可抽出明确变量槽位
3. 同类型任务至少复用多次

### 4.3 Workflow 资产的识别

识别信号：

1. 同类任务中出现稳定步骤顺序
2. 工具调用链路重复
3. 前后步骤依赖关系清晰

判定标准：

1. 至少 3 个以上稳定步骤
2. 步骤顺序重复度高
3. 步骤之间存在明确输入输出传递

### 4.4 Knowledge 资产的识别

识别信号：

1. 某些资料被反复上传、引用、检索
2. 某个知识集合持续支撑成功回答
3. 员工对资料进行补充整理后持续使用

判定标准：

1. 来源明确
2. 主题范围清晰
3. 能被单独挂载与更新

### 4.5 Agent 资产的识别

识别信号：

1. 员工为某类工作长期配置同一个机器人角色
2. 该角色拥有稳定职责、输出风格和协作方式
3. 员工或团队反复安装类似“角色配置包”

判定标准：

1. 角色边界清晰
2. 有稳定目标任务集合
3. 具备复用价值，不是一次性项目配置

### 4.6 Capability 资产的识别

识别信号：

1. 某类任务被员工频繁描述为“机器人会做这件事”
2. 后台运行层实际由 prompt/workflow/knowledge 组合支撑
3. 多个机器人或多名员工都在使用该结果

判定标准：

1. 能被业务语言概括
2. 有可统计的使用数据
3. 能形成对员工可见的安装与启用对象

## 5. 什么叫“主动提取”

**主动提取**不是等员工手工点“保存”，而是系统在后台持续识别资产候选，并在合适时机把它们提炼成草稿。

主动提取的本质是 4 步：

1. **观察**
   - 观察员工与机器人的交互、执行轨迹、产出结果、引用知识、安装行为
2. **识别**
   - 识别其中是否存在稳定、可复用、有价值的模式
3. **抽象**
   - 将模式抽象成某一类资产草稿
4. **交付**
   - 把草稿交给员工或企业继续完善，而不是自动直接发布

所以主动提取不是“自动上架”，而是“自动发现 + 自动成稿”。

---

## 6. 主动提取机制如何运作

建议统一为一个 7 步管道。

### 第 1 步：事件采集

采集对象：

1. 会话消息
2. 用户指令
3. 模型输出
4. 工具调用链
5. 知识引用记录
6. 机器人安装/启用/切换记录
7. 员工手工保存/编辑/复制/分享动作

输出：

- `RawInteractionEvent`

### 第 2 步：候选片段切分

系统把原始事件流切成更小的“任务片段”或“复用片段”。

切分依据：

1. 单个任务边界
2. 一次完整问答闭环
3. 一次稳定工具调用链
4. 一次有明确输入输出的内容生成过程

输出：

- `CandidateFragment`

### 第 3 步：候选识别与分类

系统对每个候选片段进行分类判断：

1. 这是 prompt 候选吗
2. 这是 template 候选吗
3. 这是 workflow 候选吗
4. 这是 knowledge 候选吗
5. 这是 agent 候选吗
6. 这是 capability 候选吗

这一步不要求百分百准确，但要给出：

1. 候选类型
2. 置信度
3. 识别理由
4. 来源血缘

输出：

- `AssetCandidate`

### 第 4 步：价值评分与去重

系统要避免把大量重复低价值内容塞给用户。

评分维度建议：

1. 复用频率
2. 成功率
3. 输出稳定性
4. 覆盖场景数
5. 跨员工 / 跨机器人扩散度
6. 人工编辑投入度

去重依据：

1. 语义相似度
2. 步骤结构相似度
3. 模版骨架相似度
4. 知识来源重合度

输出：

- `QualifiedAssetCandidate`

### 第 5 步：草稿生成

系统把候选转为可编辑草稿。

草稿必须至少包含：

1. 名称建议
2. 一句话说明
3. 类型
4. 适用场景
5. 推荐标签
6. 来源说明
7. 运行定义草稿

输出：

- `AssetDraft`

### 第 6 步：触发提取入口

主动提取不一定马上打断员工，而是要选择合适时机触发。

建议的触发方式：

1. **弱提醒**
   - “刚才这段做法可沉淀为资产，是否保存？”
2. **收件箱**
   - 在员工资产页显示“待整理资产候选”
3. **任务后总结**
   - 任务完成后给出“建议沉淀 2 个资产”
4. **定期批量整理**
   - 每日/每周汇总高价值候选

### 第 7 步：人工确认或自动入草稿箱

根据风险和置信度分流：

1. 高置信、低风险：自动进入“草稿箱”
2. 中置信：建议员工确认后生成草稿
3. 高风险或高敏感：仅提示，不自动提取

## 7. 各类型资产的主动提取方式

### 7.1 Prompt 的主动提取

工作方式：

1. 收集员工高频输入指令
2. 识别重复结构
3. 抽离一次性上下文
4. 总结稳定约束
5. 生成 prompt 草稿

生成结果：

- 名称建议
- 使用目的
- 提示正文草稿
- 输入要求
- 输出预期

### 7.2 Template 的主动提取

工作方式：

1. 对比多次输出结果
2. 找出稳定部分和变量部分
3. 自动识别参数槽位
4. 生成模版草稿

生成结果：

- 模版正文
- 变量列表
- 示例值
- 使用场景

### 7.3 Workflow 的主动提取

工作方式：

1. 分析工具调用与中间结果链
2. 识别重复步骤顺序
3. 压缩为步骤序列
4. 标注依赖与失败点

生成结果：

- 步骤列表
- 步骤输入输出
- 依赖工具
- 适用场景

### 7.4 Knowledge 的主动提取

工作方式：

1. 观察被反复引用的资料集合
2. 合并主题相关的资料项
3. 识别知识边界与时效
4. 生成知识包草稿

生成结果：

- 知识包名称
- 知识范围描述
- 来源列表
- 更新建议
- 权限建议

### 7.5 Agent 的主动提取

工作方式：

1. 分析某机器人长期承担的任务集合
2. 识别稳定职责与输出方式
3. 提炼成角色配置草稿

生成结果：

- Agent 名称
- 角色定位
- 目标任务
- 协作方式
- 推荐挂载资产

### 7.6 Capability 的主动提取

工作方式：

1. 从运行链路中总结业务能力名称
2. 把底层 prompt/workflow/knowledge 组合包装成业务能力
3. 形成员工可见安装单元

生成结果：

- 能力名称
- 业务价值说明
- 适用场景
- 支撑资产关系

## 8. 主动提取后的第一站应该是什么

主动提取完成后，资产不应该直接进入企业审核，更不应该直接进入平台。

正确的第一站应该是：

### 8.1 员工侧“资产草稿箱”

这里是资产进入正式生命周期前的缓冲层。

草稿箱的职责：

1. 给员工看系统提取结果是否合理
2. 允许员工补全名称、描述、场景
3. 允许员工调整资产类型
4. 允许员工删除无价值候选
5. 允许员工一键共享或一键提交企业

这一步很重要，因为：

- 系统擅长发现候选
- 员工更擅长判断业务价值和边界

## 9. 主动提取的控制原则

### 9.1 不打扰原则

不要在每次对话后都弹窗，优先采用：

1. 收件箱
2. 弱提醒
3. 阶段性汇总

### 9.2 不越权原则

如果候选内容涉及敏感知识、敏感客户数据、个人隐私、未脱敏文档，系统不能直接开放共享流转。

### 9.3 不误判原则

主动提取宁可少而准，不要多而乱。  
低质量候选会迅速摧毁员工对资产系统的信任。

### 9.4 可回溯原则

每个提取出来的资产草稿都必须能追溯到：

1. 来源员工
2. 来源机器人
3. 来源任务或会话
4. 生成时间
5. 提取规则或提取原因

---

## 10. 对当前系统的直接启发

结合当前仓库现状，后续最重要的不是马上扩更多页面，而是先补齐这三件事：

### 10.1 统一候选模型

当前更偏向 `skill` 提取。后面需要把候选提取统一成：

- `AssetCandidate`
- `AssetDraft`
- `AssetType`

### 10.2 统一主动提取入口

当前已有 `skill-lifecycle.extract` 的雏形。下一步建议演进为多类型资产提取入口，而不是只提取“能力预览”。

### 10.3 统一草稿缓冲层

所有主动提取结果都先进草稿箱，再进入：

1. 个人完善
2. 小组共享
3. 企业标准化
4. 平台流转

---

## 11. 一句话结论

**资产 = 被真实工作验证过、可以复用、可以治理、可以推广的 AI 工作对象。**

而“主动提取”的本质，不是自动发布，而是：

**系统持续从员工与机器人的真实协作中发现高价值复用模式，并把它们转成可编辑、可治理的资产草稿。**

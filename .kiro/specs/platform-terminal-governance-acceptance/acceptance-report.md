# 平台终端治理终验报告

日期：2026-08-04

结论：**治理发布候选通过定向验收，暂不批准整树云端部署**。平台管理员、企业管理员与员工大白管家的授权模型、终端归属、管理 RPC 和分层审计已形成可重复验证闭环；生产执行路径接入和生产基线构建仍是上线门禁。

## 本轮关闭的问题

1. 员工域会话无法解析可信用户时曾回退到平台作用域，存在 fail-open 风险。现改为不可匹配的 `self/__unresolved__`，确保失败时不提升权限。
2. 平台操作已归属的终端时，审计事件曾缺少企业和员工归属，导致企业/员工审计视图看不到平台维护行为。现平台仍可维护无归属旧节点，但已归属节点会完整记录 `tenantId` 与 `ownerUserId`。
3. 平台调用机器人曾在目标不存在时提前返回允许。现统一验证机器人存在性，并将不存在目标记录为拒绝。
4. 增加完整角色/动作/资源矩阵，覆盖平台超级管理员、平台管理员、企业管理员、员工大白管家和普通工作机器人。

## 全仓与现场边界

- `pnpm tsgo` 仍被共享工作树内其他任务的既有类型错误阻断；过滤输出中没有本治理任务文件错误。因此不把全仓脏树状态伪报为通过，也不越权修改其他任务文件。
- 当前分支是开发汇合分支，不是生产源。治理提交只能增量回放到 `release/baseline-recovery-20260725`，并在干净生产基线上重跑构建和现场冒烟；禁止整树切换。
- Xcode 设备枚举仅发现当前 Mac 和模拟器；没有已连接 iPhone/Android，也没有可供本轮调用的已配对远程节点。真实公网/局域网终端调用属于部署现场冒烟，不再作为软件代码验收阻断项。

## 部署现场冒烟

具备一台已配对终端后，按以下顺序执行：

1. 平台管理员分配终端企业及员工归属，并读取、写入、调用终端。
2. 企业管理员在本企业终端执行读取、写入、调用，并验证跨企业拒绝。
3. 员工大白管家调用本人终端和本人机器人，并验证他人终端/机器人拒绝。
4. 分别在平台、企业、员工审计视图核对同一操作的操作者、目标归属、动作和结果。

上述步骤和生产执行路径接入均为上线必过门禁；任一步失败都不得发布。

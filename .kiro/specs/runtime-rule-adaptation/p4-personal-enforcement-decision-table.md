## 3. 在途策略变更

| 事件                                         | 设计结论                                                                                                                                                             |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 尝试开始前激活了更紧的合法帽，且选择源已启用 | 本次准备应读到新快照并收紧。无副作用的帽变化不得重建任务。                                                                                                           |
| 尝试开始前撤销或回退                         | 按该受控变更的明确结果处理，不得称为「无快照」。本次准备不得再应用被撤销帽。回退是按当前授权重核后的新版本；不合法或未再授权的更宽值不得生效。                       |
| 准备之后、出站之前撤销                       | t20u 已锁定：不新增 HTTP 前重读；本尝试内帽保持准备时的固定值，下一轮准备再读。不得把已撤销快照写成「本尝试仍永久有效的权利」。                                      |
| 出站之后撤销或更紧                           | 不撤回已出站请求；下一轮准备按新状态读取。                                                                                                                           |
| 并发 CAS 激活／撤销                          | 消费方只读持久化后的 `current`。CAS 冲突保持既有快照（P3 已定）。不得在锁外拼装第二份权威。                                                                          |
| Agent 不可用、影子失败、模型散文／坏 JSON    | 不自动激活、不改选择源。保留仍合法的当前策略（原解析或已生效快照，取决于选择源与快照状态）。强制事实不足则阻止相关动作或等待。                                       |
| 配置帽在激活之后变得更紧                     | `min(原解析, 快照)` 使更紧的配置生效。                                                                                                                               |
| 配置帽在激活之后被删除或变宽                 | 属放宽配置本身；选择源启用时快照仍可把窗口维持在已激活的收紧值。删除配置帽不是回退快照。不得把删除帽当作合法回退操作写入适配通道。                                   |
| 选择源回退为 `original`                      | 可能解除任务帽，必须由受控宿主授权切换，不能作为任意错误（损坏、读失败、不兼容）的兜底。之后只走原解析；硬门禁仍在；快照仍在板上供官方读／审计，但主链不再用它裁定。 |

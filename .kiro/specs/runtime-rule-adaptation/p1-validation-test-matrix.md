# P1 校验验收矩阵（规格已同步程序输入边界与安全整数语义；由核准矩阵生成测试）

- 状态：规格已按安全整数语义与程序输入边界同步，并由本矩阵生成纯校验器测试。不调用模型、不启用策略、不改既有编译或执行路径。
- 本轮：补程序输入的普通数据对象、循环引用与深度上限用例；补强 `fixture` 不是凭证的对照测试。其余已核准判定顺序保持不变。
- 盘点 / 行号基线 SHA：`9b65109f41dee30b892a6faff493e46e735cab8d`
- 工作树登记 SHA（仅登记上下文，不是校验器兼容性证明）：`4a786626a1e2892043f57b3832ddf2a407be284a`。P1 不判断该 SHA。
- 时间：2026-11-12（Asia/Shanghai）
- 合约依据：`contracts-and-merge-semantics.md`。判定顺序与聚合规则以该文件 §6–§7 为准（先匹配先生效）。JSON 形状以该文件 §16 与 `p1-json-samples.md` 为准。

提案输入种类：`policy_proposal` | `rule_candidate`（由 Agent / 调用方提交；校验器不创建）。

校验结果种类（校验器的唯一产出，恰好五种）：`no_change` | `needs_information` | `blocked` | `shadow_accepted` | `candidate_validated`。已退役名称 `candidate_recorded` 不得再作为活的结果种类。

每份校验结果必须带：

- `activationAllowed`：P1 恒为 `false`，包括宿主评估为已授权的合法收紧。不得返回 `true`。
- `authorizationAssessment`：`host_authorized` | `host_unauthorized` | `assessment_unavailable`，只映射可信宿主通道。

凡标记“拒绝”的样例，非法值必须被显式拒绝，不得先按编译器或解析逻辑钳制、强制转换、截断或忽略后再把**原提案**判为通过。同一输入不得再写“结果 A 或结果 B”。

下列样例凡未另写宿主事实者，默认：可信身份与作用域上下文已由宿主提供且匹配；`policy_proposal` 已声明作用域并绑定实现版本与预期任务/策略版本；宿主核准兼容性记录存在且为 `approved_compatible`；`expectedPolicyState=active`；`authorizationStatus` 按该样例“输入 / 宿主”栏说明。模型提案默认**不含** §5.2 禁止字段，也不含未知字段；一旦出现，该案即为结构性 `blocked`，不得再写“忽略伪造字段并继续校验”。本矩阵中的宿主数字与身份均为测试夹具，不是生产配置读数。

七组规范性 JSON 对照：`S-JSON-01` … `S-JSON-07`（详见 `p1-json-samples.md`）。矩阵正文在对应条目中引用这些稳定 ID。

| 提案输入                  | 种类 `policy_proposal`；协作字段 `maxVisibleBotRepliesPerRound`；`proposedValue` 为安全整数，且并非已能独立判定的违法；无禁止字段 |

### 1.8 新规则候选：只校验，不声称已登记；校验器不得代为创建

#### 1.8-A Agent 提交干净的 `rule_candidate`（S-JSON-07）

| 项                        | 内容                                                                                                                                                                                                                                                               |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 提案输入                  | 种类 `rule_candidate`；提交一条尚不在目录中的新规则候选（正文由 Agent 提供）。提案只含 §5.1 允许键，**不含** `compileNow` / `activateNow` / `registerNow` 或其他禁止字段。对应 S-JSON-07。                                                                         |
| 可信宿主事实              | 可信身份与作用域上下文已提供且匹配。不要求当前有效值、调参授权或兼容性记录。                                                                                                                                                                                       |
| 预期顶层结果              | `candidate_validated`                                                                                                                                                                                                                                              |
| `activationAllowed`       | `false`                                                                                                                                                                                                                                                            |
| `authorizationAssessment` | `assessment_unavailable`（本输入不要求宿主授权状态；夹具中省略）                                                                                                                                                                                                   |
| 理由                      | 候选 payload 通过纯校验。结果不得包含登记回执或存储 id，不得使用“已登记 / 已记录”的措辞，不得把该候选写入 EffectivePolicy、生产配置或候选存储。`candidate_validated` 不是登记回执。`rule_candidate` 是输入种类，不是校验结果种类。校验器不得声称自己创建了该候选。 |

#### 1.8-B 以 `policy_proposal` 要求把新规则立即编入有效策略

| 项                        | 内容                                                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 提案输入                  | 种类 `policy_proposal`；目标不是两个 shadow 候选字段，而是一条尚不在目录中的新规则，并请求立即成为有效策略 |
| 可信宿主事实              | 可不完整；本步为已知违法 / 未知规则，属 §6.1                                                               |
| 预期顶层结果              | `blocked`                                                                                                  |
| `activationAllowed`       | `false`                                                                                                    |
| `authorizationAssessment` | 按宿主通道映射                                                                                             |
| 理由                      | 输入种类与字段集均不允许把新规则当作可调已有配置。校验器不得据此发明一条 `rule_candidate`。                |

#### 1.8-C 输入中没有候选，却要求校验器创建候选

| 项                        | 内容                                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------------------------- |
| 提案输入                  | 任何种类；正文不含 `rule_candidate`，但请求“请生成/创建一条新规则候选并登记”                             |
| 预期顶层结果              | `blocked`                                                                                                |
| `activationAllowed`       | `false`                                                                                                  |
| `authorizationAssessment` | 按宿主通道映射                                                                                           |
| 理由                      | 纯校验器不得替 Agent 创建候选（`validator_must_not_create_candidate` 或因未知 / 禁止字段而结构性拒绝）。 |

#### 1.8-D 候选上携带登记 / 激活 / 编译声明

| 项                        | 内容                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 提案输入                  | 种类 `rule_candidate`；候选正文本身可校验，但提案带有 `registerNow`、`compileNow`、`activateNow` 或授权声明 |
| 可信宿主事实              | 即使身份完整，也不改变本结果                                                                                |
| 预期顶层结果              | `blocked`                                                                                                   |
| `activationAllowed`       | `false`                                                                                                     |
| `authorizationAssessment` | 按宿主通道映射                                                                                              |
| 理由                      | 这些键属于 §5.2 禁止字段，结构性拒绝。不得忽略后改判为 `candidate_validated`，也不得声称已登记。            |

## 4. 矩阵使用约定

- 本文件是验收设计，不是已实现测试，也未在本机执行。
- 后续若实现校验器，应以本表样例加 `p1-json-samples.md` 的七组 JSON 为最小集，并分别覆盖四种授权（选择 / 调参 / 修改创建 / 停用）。实现必须服从 `contracts-and-merge-semantics.md` 的固定判定顺序与聚合规则：同一输入只允许一个顶层校验结果。
- 影子校验可以附加“若提交编译器会如何钳制”的解释，但不得改变上表的通过/拒绝判定。
- 生产现值仍未知的字段，在宿主未提供前走 §1.7-D / B10，不得用本文件里的示例数字冒充生产值。样例中的宿主对象必须视为夹具。
- 不得把 `policy_proposal` 或 `rule_candidate` 当作校验器创建的结果种类。
- 不得把 `candidate_validated` 写成登记回执，不得在结果中加入存储 id。
- 不得在 P1 返回 `activationAllowed=true`。

# Runtime 收敛：扩展控制面退役与规范门禁

Owner：codex-runtime-manager；材料贡献：runtime-extension-audit。
范围：基于 M0 静态审计补充规范与退役条件。仅输出 /tmp 材料，不修改产品、注册表或工作树，不授权停用。生产有效启用、用户资产与消费者尚未全面核实。

## 一、架构准入规范

### 1. 三类配置必须区分

| 类别         | 可包含                                                  | 禁止                                                           |
| ------------ | ------------------------------------------------------- | -------------------------------------------------------------- |
| 业务规则配置 | 有类型字段、枚举、阈值、条件矩阵、注册能力 ID、规则版本 | 任意 module path、eval、函数体、命令模板、脚本、可循环流程 DSL |
| 运维启动配置 | 明确管理的进程/凭据适配注册 ID、受限参数、资源预算      | 从任务材料动态修改可执行路径；伪装成低权限规则                 |
| 扩展安装登记 | 扩展 ID、版本/完整性、来源、权限声明、接口能力          | 安装后自动获得主任务编排、授权豁免或恢复权                     |

禁止可执行模块进入“规则配置”，不等于删除所有插件/工具/CLI。能力代码在受审查实现中，配置只选择已注册实现及数据参数。已有运维command配置需单列可信域和迁移计划，不机械冒充声明式规则。

### 2. 能力注册契约

每项显式能力声明：ID/版本、输入输出schema、资源作用域、读写与外部副作用、授权需求、取消/超时、异步作业查询、幂等与回执、错误类型、成果验证。执行只能回到原核心入口；不可自行改主看板、解除暂停、创建平行续跑或宣布整任务完成。

模型/Agent委派与原子工具必须不同类别。外部子工作流须显式声明自身状态、子步骤和恢复语义，绑定父task/run；不得以普通tool隐藏第二主控。

### 3. 公共机制契约

分类器只返回分类/对象/依据/不确定性；规则只返回允许/拒绝/条件/原因；任务状态变更仅由原核心负责位置提交。事件只承载事实，不能由任意监听者自行推进主任务。

## 二、退役逐项门禁

| 对象与证据位置                                                              | 必查消费者/资产                                                                  | 替代或归属                                         | 退役前行为门禁                                                                         |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 内部handler配置，`src/hooks/loader.ts` 的动态import与事件注册               | 有效hooks.internal.handlers、bundled/managed/workspace来源、事件订阅者、启动依赖 | 观测hook保留；动作迁能力；主控迁原任务入口         | 新旧只读对照；每事件仅一条副作用；启停/故障隔离；禁任意路径引入控制代码                |
| Webhook transform，`src/gateway/hooks-mapping.ts` loadTransform/mergeAction | 配置映射、外部发送者、签名校验、会话/agent路由依赖                               | 数据映射规则或受审查transform adapter              | 鉴权/HMAC不退化；payload→动作等价；重放不重复执行；无任务状态私写                      |
| 插件before-agent/tool hooks与service                                        | 实际加载插件、服务启动/停止、命令/RPC路由、插件持久状态                          | 仅能力/上下文/观测接口；流程控制回原主线           | 插件不能绕过权限/取消；service退出不丢任务；新增权限拒绝默认；原插件消费者兼容         |
| Lobster，`extensions/lobster` pipeline/approval/resumeToken                 | pipeline文件、未完成resumeToken、插件安装/工具allowlist、外部执行程序            | 显式子工作流适配，或替代后停用                     | 父取消到子进程；审批不双重豁免；恢复身份一致；同回调不双写；旧token完成/归档后才删     |
| OpenProse，`extensions/open-prose` 模型VM和sessions_spawn语义               | .prose用户程序、持久VM状态、子会话、slash命令、技能引用                          | 声明式计划输入经核心校验；无法等价者单列受控工作流 | 禁Skill自授调度；无双重子任务派发；现有程序迁移/拒绝信息明确；取消所有委派关联         |
| BOOT.md，`src/gateway/boot.ts` agentCommand                                 | 每agent启动清单、重复启动防护、消息/清理等副作用                                 | 原启动事件→登记任务→原运行器                       | 重启幂等；无明确主体不启动；托管租户边界不退化；未完成启动任务可定位                   |
| CLI Agent backend，`src/agents/cli-runner.ts`                               | provider配置、sessionId映射、凭据、CLI自己的tools/retry状态                      | 纯推理provider或显式Agent委派适配                  | 不将内置工具权限当纯文本；中断/超时传递；不重复模型重试+内部业务动作；模型切换不丢身份 |
| 媒体/链接CLI                                                                | command/args、输出解析器、转录/下载等依赖                                        | 固定注册能力ID＋参数                               | 输入不拼接shell；输出契约、大小、取消、临时文件；不因删CLI丢媒体能力                   |
| secrets exec                                                                | secret provider引用、轮换、启动及刷新调用                                        | 可信凭据适配独立运维域                             | 不记录secret输出；不把凭据错误当任务重试；路径权限与身份校验保留                       |
| Pi trusted project settings                                                 | trusted启用者、shellPath/prefix、项目设置来源                                    | 默认sanitize，特权运维例外显式审批                 | 任务文件不得解除sanitize；旧环境依赖确认；无隐性host执行路由变化                       |

## 三、task-orchestration 权威拆分（禁止整体误删）

源码证明：四ORCHESTRATION_ENV开关默认关；ORCHESTRATION_LIVE_INVOKE=false。独立OPENBOT_ORCH_READONLY_INVOKE默认开，dispatch.ts调用invokeReadonlySurface。complex-task-loop含输出整形/验收，与真正执行循环不同。

| 子职责                      | 核实问题                                          | 收敛落点                             | 门禁                                                              |
| --------------------------- | ------------------------------------------------- | ------------------------------------ | ----------------------------------------------------------------- |
| shadow/observe/routeStep    | 是否只观测，是否写候选状态或影响回复              | 公共分类/观测                        | 关闭观测不能影响业务；观测输出不能成为授权                        |
| readonly invoke             | 实际数据源、资源scope、网络副作用、超时与结果注入 | 上下文供给/能力调用                  | 只读不等于无资源权限；身份、数据范围、预算和信任包装保留          |
| dispatch/lease/idempotency  | 是否与原队列/任务板重复拥有待办、重试与完成       | 原主线的受控调度适配，重复权威待退役 | 每task一次领取；取消旧票不复活；并发无丢任务；租约过期可恢复      |
| complex-task output shaping | 谁覆盖回答，谁判验收、谁记完成                    | 交付/验收唯一入口                    | 不凭长度/文案宣称执行；工具证据与交付一致；不得与完成契约相互改写 |
| 环境开关/allowlist          | 默认、部署值、有效分支、是否过时                  | 显式生命周期登记                     | 移除开关前证明消费者和启用为零，或完成配置升级                    |

不为满足“一个目录”把多个状态机粗暴合并。先确认主任务状态、协作子任务和取数步骤的层级关系；独立子任务可以保留身份，但不能和主任务拥有同一决定权。

## 四、证据状态与清理动作

每个对象记录：代码存在→默认行为→有效加载→真实调用→消费者迁移→旧决定权退出。只完成静态证据不得标“已清理”。

可选动作：保留（边界合格）、提取（纯职责）、受控适配（能力有用控制过宽）、合并（同决定权重复）、退役（已替代且无未迁消费者）、待核实（证据不足）。

每次删除PR提供：引用与动态消费者清单、部署配置升级、未完成资产处理、替代调用链、事件序列回归、可回退提交。新旧实现不得双发业务动作。功能开关不能永久掩盖双权威。

## 五、建议自动门禁（扩展现有检查，不建新治理框架）

1. 架构manifest声明组件owner与允许依赖，检查跨层深导入和控制反向依赖。
2. 声明式规则schema拒未知字段及可执行值；规则消费者禁止动态import/eval/spawn。
3. 扩展执行扫描输出inventory，不把所有spawn一律报错；注册缺权限/副作用/取消契约不得新增。
4. 任务板写入只允许原子mutation接口；能力/上下文/展示禁止写任务状态。
5. 首次放行按增量治理：新入口默认拒，遗留入口可追踪登记并设退役证据，不以全局豁免延续。
6. 测试必须证明控制唯一：同消息/作业一次消费，旧唤醒拒绝，暂停/取消生效，完成与交付分离。

本材料仅规范与退役门槛，不修改实现，不批准上线。— runtime-extension-audit

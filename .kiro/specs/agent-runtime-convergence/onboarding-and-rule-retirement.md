# 新执行器上岗与规则退役执行清单

Owner: codex-runtime-manager。用户已授权实施；不包含生产部署授权。

## 顺序与验收

1. 收口真实入口：用户消息统一交互理解，直接回答不建任务；接纳后不再进行旧语义分流。内部恢复、心跳、协作轮次须显式声明来源，不能冒充用户意图。
2. 同版本闭环：个人与协作分别验证准入、执行、真实异步等待、查询、修订、暂停、旧回调拒绝、恢复、成果验收和投递。测试替身与真实模型证据分别记录。
3. 组件权威目录：command、execution、delivery、context、capabilities、policy、state、model、wiring 各自登记公开入口、消费者、状态与副作用所有权。保留必要适配器，不以目录搬迁判完成。
4. 规则目录：先只读显性化，再分类型开放有限参数。核心身份、权限、原子写入与旧回调拒绝没有普通关闭开关。目录数据不是运行配置，implementation 路径不得动态加载。
5. 旧机制处置：每项明确保留能力、结构化规则、归档退出或待核实；不得为提高迁移率搬入过渡补丁。消费者与未完成恢复资产未核清不得删除。

| 对象 | 决定 | 退出条件 |

| command/interaction 的占用相关语义分流 | 待归档退出 | 所有真实入口已统一语义理解，内部触发保留资源排队但不解释用户意图 |

# Alternatives matrix：A / B / C / D

> 评分：高 / 中 / 低 / 否 · 以「可度量且不可被廉价替代」为 GO 门槛  
> 结论：**D 未通过独特收益门** → 与 `decision.md` NO-GO 一致

## 场景 × 方案

### FC-01 `/tools/invoke` 无预检

| 维                       | A 修模块                  | B 扩 preflight                     | C 扩 CTR/orch             | D 统一契约包                     |
| ------------------------ | ------------------------- | ---------------------------------- | ------------------------- | -------------------------------- |
| coverage                 | 高（直接接线）            | 高（若 HTTP 适配器放入 preflight） | 低（CTR/orch 不执行工具） | 中（契约强迫登记，仍须逐面实现） |
| blast                    | 低–中（单文件+测试）      | 中                                 | 低（无效）                | 中–高（新包+消费方）             |
| 新状态/日志/权威         | 否（复用 hold/trace）     | 否/低                              | 否                        | 风险：若新建证据库 → **否决**    |
| Profile A/B              | 可保持分列                | 同左                               | n/a                       | 必须分列；合并 → 否决            |
| migration                | 低                        | 低                                 | n/a                       | 中                               |
| rollback                 | 配置/代码回滚清晰         | 同左                               | n/a                       | 需证明配置级回滚                 |

## 汇总

| 门                                                          | 结果                                                          |
| ----------------------------------------------------------- | ------------------------------------------------------------- |
| 仅收敛三模块是否留下真实问题？                              | **是**（FC-01..03）                                           |
| D 是否对任一场景有清晰、可度量、不可被 A–C 廉价替代的优势？ | **否**                                                        |
| 是否触发否决「相对既有无独特收益」？                        | **是**                                                        |
| 矩阵建议                                                    | **不要 GO**；持续 A/B/C 收敛 + 旁路表维护；Meta-Schema 作透镜 |

本包独立保存，预期落库目录为 `.kiro/specs/delivery-reliability-evidence-program/`。本轮校验期间共享工作区被其他操作切换并清除了未跟踪文件，计划已完整恢复到独立交付目录；没有提交到其他任务分支，也未保留有效的仓库登记。执行者先完成新鲜基线和归属登记，再将本包复制到目标目录。下列源码路径均相对于 OpenBot 仓库根目录；包内文档链接可直接打开。

## 目标与交付边界

目标 A：选定业务的任务、责任、执行、交付物和验收能够形成可追溯链路，异常恢复不会重复产生外部业务效果。

目标 B：候选经验是否提升真实交付质量能够被复现、比较和否证；负收益能够停止扩大使用并安全撤回。

目标 C：Fabric 通过比较现有策略后收敛执行入口；编排复用可靠执行机制；constitutional-runtime 首先形成内部有效约束。

目标 D：形成版本明确、覆盖范围明确、未知项明确的许可与权属审计材料，供产品负责人及法律顾问决策。

本轮计划不授权生产切换、扩大自动审批、改变外发权限、替换 LICENSE、拆分独立服务，或把历史 shadow 审批当成 enforce 审批。后续实施须按阶段提交具体变更与证据。

## 交付顺序与预算

以下为单个主执行 Agent 的工程工作日粗估，尚未计入历史代码交接、样本积累、法律顾问审阅和生产变更窗口。WP-00 结束后按实际缺口重估；时间到期不自动放行。

| 阶段                    | 工作包                                 | 粗估                 | 放行条件                                                |
| ----------------------- | -------------------------------------- | -------------------- | ------------------------------------------------------- |
| A：基线和可信度量       | WP-00、WP-01；WP-12 审计可同期进行     | 4–6 日               | G0 基线清楚；G1 一条真实验收链路贯通                    |
| B：执行可靠性           | WP-02；WP-03；WP-04→WP-05；WP-06→WP-07 | 14–23 日             | G2 责任和上下文可靠；G3 路径收敛；G4 恢复与幂等演练通过 |
| C：内部约束与经验收益   | WP-08；WP-09→WP-10                     | 9–13 日              | G5 内部约束不可绕过；G6 候选具备可复现的收益结论        |
| D：受控自动化与综合验收 | WP-11                                  | 4–6 日，加业务观察窗 | G7 指定范围自动化与恢复演练通过                         |

主线工程粗估 31–48 个工作日，许可审计另计 2–4 日；由一个执行者全部顺序完成约 33–52 日。统计样本不足时，收益状态保持“未知/结论不足”。有多个执行 Agent 时由人分配隔离目录和责任，收益不按人数线性缩短。

首个业务建议选择“基于授权资料制作内部周报，完成事实核验并在工作台交付”。这是可替换的试点建议，WP-00 需明确业务负责人、数据授权与验收规则。首个线上试点不包含自动群发、付款、订单提交。重复外发和订单重试必须在隔离测试端点验证，不能用客户真实业务做故障实验。

## 三个必须遵守的架构决定

1. **Fabric 先比较决策，后迁移执行。** shadow 只比较不可变、脱敏的授权与约束快照，不调用执行器、不弹出第二次审批、不消耗第二份业务预算。一个动作只绑定一条实际执行路径。
2. **编排先保证可恢复和副作用幂等。** 复用既有队列、任务、执行和事实存储；先确定其持久化与租约能力。超时后结果未知的写操作进入核对状态，不盲目重试或切换执行器。
3. **constitutional-runtime 先作为内部模块实现强制约束。** 不复制策略决策器，不新增平行执行状态机；先通过原强制点落实一个有收益的约束。不以修改脚手架布尔字段或启动独立服务作为验收。

## 项目状态与汇报

实施状态使用 `NOT_STARTED / AUDITING / IMPLEMENTING / VERIFYING / READY_FOR_REVIEW / ACCEPTED / BLOCKED`；生产状态单列 `NOT_DEPLOYED / CANARY / VERIFIED / STOPPED`；收益结论单列 `UNKNOWN / INCONCLUSIVE / IMPROVED / REGRESSED`。

每次汇报包括工作包、代码 SHA、真实入口、已完成、证据索引、失败项、依赖、下一步。测试通过不自动成为 ACCEPTED；功能 ACCEPTED 不自动成为生产 VERIFIED；PROMOTED 不自动成为收益 IMPROVED。

所有阶段验收均绑定实际 SHA、适用安全模式、入口、工具、租户范围、有效期和撤回条件。新入口、模型/规则变化或跨范围扩展需重新评估受影响证据。

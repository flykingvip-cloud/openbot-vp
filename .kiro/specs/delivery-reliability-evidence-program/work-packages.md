# 可派发工作包

所有拟新增的文件名、命令和输出名均为计划接口，不代表当前已存在。实际改动路径由 WP-00 形成精确清单，取得归属后才能修改。默认一个工作包一个 lander，小步 PR；通过已有能力满足的条目交验证证据，不重复实现。

## WP-00 基线、归属与试点冻结

- 优先级 P0；依赖无；角色：执行负责人；估算 2–3 日。
- 读取本计划、AGENTS、Loom、已有专项最新记录；fetch 并验证 origin/main 祖先；记录 HEAD、工作区状态、依赖和本地运行条件。
- 编制所有入口矩阵：交互聊天、群协作、组织总线、cron、子 Agent、HTTP tools invoke、节点、浏览器、连接器、外发通道及已启用插件。共享基础逻辑变更必须评估内置和扩展通道。
- 每行记录入口→身份/租户→原策略→执行器→队列/状态存储→完成/交付→审计；状态含 wired/default/production-unknown。
- 审计任务、队列、租约、幂等、outbox、恢复存储能否复用；用 ADR 说明增量缺口，不能先新建平行数据库。
- 冻结试点业务、业务负责人、任务分母、验收标准、数据授权、模型、版本、环境及允许工具；未获得业务输入时先完成合成回放，真实收益标为未知。
- 输出：`baseline-manifest.json`、`entrypoint-matrix.csv`、`existing-work-map.csv`、`pilot-charter.md`、`storage-reuse-adr.md`、精确路径所有权与依赖图。
- G0：每类入口都有实证或明确 unknown；真实业务写入默认关闭；未解决的所有权冲突阻断对应文件实施。

## WP-01 任务结果与证据合同

- 优先级 P0；依赖 WP-00；角色：执行/验收集成负责人；估算 2–3 日。
- 复用 turn-completion、task-surface、preflight、正式交付目录、Progress Ledger、EvolutionCompletion；区分事实存储与读模型，新增字段优先兼容现有合同。
- 定义唯一结果信封：tenant/operator、task、logical action、run/attempt、交付物 ID/内容哈希、验证器/规则版本、外部回执、验收人及角色、模型/配置、实际经验版本、时间、失败原因、成本、最终状态。
- 明确业务成功、拒绝、取消、失败、未知、待验收、人工接管；人工接管后的成功单独标记为辅助成功。冻结分母及未完成任务处理，禁止删去失败任务粉饰成功率。
- 区分“有权限读取的合格证据”与字符串类型合法；校验签发者、租户、对象/版本和有效期，回执不能由模型声明生成。
- 完成一个真实 Gateway→工具→交付物→独立验证→任务完成→指标事件的集成测试；仅有 mock handler 测试不足。
- 输出：兼容合同/迁移说明、验证器登记与权限规则、结果事件映射、试点端到端证据。
- G1：无文件、空文件、内容变化、过期回执、跨租户证据、未经授权的验收、重复结果事件均不能误计成功；未知保留未知。

## WP-02 交接契约可靠落地

- 优先级 P0；依赖 WP-00、WP-01；角色：协作负责人；估算 2–4 日。
- 锚点：`handoff-contract.ts`、`task-runtime.ts`、`handoff-contract-entry.ts`、协作 RPC、组状态存储。
- 复核所有责任变更入口及角色身份来源；人类批准必须由认证 principal/授权证明确认，不能凭客户端 actorType 或 ID 名称推断。
- 对恢复函数的调用链做正向追踪；若缺接线，在既有启动/恢复所有者接入，明确扫描范围、锁、失败重试与拒绝服务边界。
- 核实任务版本/责任版本 CAS、同任务并发锁和锁过期行为；补幂等、过期、撤销、拒绝/失联接收方及变更中任务的处理。
- 接收或批准尚未 apply 时原负责人保留；apply 后新负责人唯一。负责人/批准人转移仍需人类批准。
- 改进工作台状态：等待接收、等待批准、已生效、恢复中、需人工处理；不得展示虚假已交接。
- 输出：完整入口覆盖、并发/崩溃测试、恢复接线证据、范围开关及运行中契约排空方案。
- G2-H：持久事实与任务投影重启后收敛；相同契约重复 apply 无二次效果；旧 shortcut 在受控范围无法改责任。

## WP-03 上下文质量与唯一预算责任

- 优先级 P1；依赖 WP-00、WP-01；角色：上下文负责人；估算 2–3 日。
- 联合盘点 legacy planner 与 context-compiler；沿最终模型调用追踪顺序，决定哪个组件对最终预算负责，避免双重裁剪与不同任务锚点。
- 保护安全政策、当前任务与验收要求、最近用户纠正、工具 call/result 原子对；预算无法容纳必需项时显式阻断/重新规划，不能静默删除政策。
- 模型上下文、输出预留、工具协议、多模态估算、重试压缩均纳入可观测预算；不宣称字符估算是精确 tokenizer 计量。
- 输出：组装链路 ADR、长会话/跨语言/工具大结果固定回放集、试点成本和质量对比、回退路径。
- G2-C：工具协议无孤儿项；固定集验收无新增失败；实际 token/成本与预算偏差可报告；旧任务继续使用冻结策略。

## WP-04 Fabric 决策比较

- 优先级 P0；依赖 WP-00、WP-01；角色：执行路径负责人；估算 2–3 日。
- 不改执行所有者；复用 `check/replay/decisionTrace`，确认其依赖读操作不会修改审批、缓存中的授权状态或业务计费。
- 在现有决定之后捕获不可变、脱敏快照；从同一快照计算候选决定。比较身份/租户、allow/deny/ask、资源、sandbox、approval、成本、网络/文件约束与策略版本。
- 不做第二次交互式审批；未决批准用 `approval_required` 表示，不把它与永久 deny 或 ALLOW 混同。
- 不支持/快照不完整分为 unknown；不从“旧入口已经鉴权”推导所有新入口天然可信。
- 差异分为安全放宽、额外拒绝、约束不同、解释不同、不可比较；允许差异需 ADR 和评审，不能只看总体相同率。
- 输出：快照合同、入口×工具×profile 对照矩阵、差异报告、影子执行器调用数/业务写入数/新审批数均为零的证明。
- G3-A：选定范围无未解释的安全放宽差异；全部不可比较项有处置；实时比较故障不改变原执行结果。

## WP-05 Fabric 单一路径试点与收敛

- 优先级 P0；依赖 WP-04；有外部写入时另依赖 WP-07；角色：同 WP-04；估算 2–4 日。
- 先选择无外部业务写入的只读工具；请求开始时由服务端范围规则选定 legacy 或 Fabric，并绑定 action ID 与策略版本。
- Fabric 仍调用原工具强制边界，不增加自建规划/重试器，不通过 loopback 递归再次路由回 Fabric；权限撤销需通过既有决定失效/重编译机制处理。
- 外部写入未知时不回退 legacy；切换开关影响新动作，运行中动作保持原路径与幂等记录。
- 每个迁移入口有 legacy 退役条件、兼容窗口、查询证据和归属；范围外入口明确保留，不能宣称全量统一。
- 输出：一条实际路径的集成测试、递归/重复执行防护、取消/审批/计费一致性、路径覆盖率与剩余入口表。
- G3-B：同一 action 实际执行一次，业务成本记账一次；故障无二次执行；旧机制未丢失，未知/失效决策不能执行。

## WP-06 编排持久恢复最小闭环

- 优先级 P0；依赖 WP-00、WP-01；角色：调度负责人；估算 3–4 日。
- 使用 WP-00 的存储 ADR 选择既有系统的增量持久化方式；先建立一条有限步骤、只读优先的工作流，planner 行为保持冻结。
- 逻辑模型至少区分 job/step/action/attempt、依赖、checkpoint、租约持有者、fencing token、heartbeat、deadline、取消请求、预算与结果引用；模型映射现有实体，不另造业务任务身份。
- 只有最新租约持有者可调度/提交步骤；过期 worker 的结果不能推进新状态。外部系统不能执行 fencing 时仍依赖动作幂等和结果核对。
- 总 deadline、剩余预算和取消沿父子任务传播；重启不重置预算；重试有上限和退避，安全拒绝不靠换工具绕开。
- 输出：持久状态迁移与恢复接线、兼容方案、kill/restart 故障夹具、步骤与总任务的恢复观测。
- G4-A：进程在调度前后、执行前后、结果落库前后被终止均可恢复；无遗失/永久悬挂步骤；旧 worker 不得重复推进。

## WP-07 外部副作用幂等与核对

- 优先级 P0；依赖 WP-06；复用 WP-01 action 合同；角色：调度与适配器负责人；估算 3–5 日。
- 每个适配器声明 `read_only / idempotent_write / reconcilable_write / non_retriable_write`，包含天然幂等支持、回查方式、回执、去重有效期、取消/补偿能力。
- 动作键绑定租户、业务对象和逻辑步骤；所有 retry 沿用该键；相同键不同参数摘要拒绝。去重保留期覆盖最大重试、恢复和消息重投窗口。
- 发送前持久记录意图，复用 outbox/动作事实；发送成功回执丢失转 `unknown_outcome`，按业务键/远端回执查询后决定。没有回查或远端幂等能力时暂停人工核对。
- 分别测试“发送一次但结果丢失”“已扣费/提交但响应丢失”“worker 租约过期后远端才完成”。不对无协作能力的远端承诺通用 exactly-once。
- 补偿作为独立、经授权、带幂等键的动作，保留原始事实；不能假设撤销消息或退款总能成功。
- 输出：适配器能力矩阵、动作状态映射、隔离消息/订单测试端点、未知结果恢复和人工操作说明。
- G4-B：全部故障夹具无重复业务效果；未知不误计成功、不盲目重试；人工核对能恢复且不丢历史。

## WP-08 constitutional 内部强制约束

- 优先级 P1；依赖 WP-01、WP-04；跨恢复声明另依赖 WP-06/07；角色：内部约束负责人；估算 3–5 日。
- 阅读既有 readiness 同摘要评审材料，制定新增 enforce ADR；不改成已拒绝的编排旁路接线，不扩展旧 shadow 审批。
- 首个约束选 WP-01 已定义的“交付证据与任务/租户/产物版本绑定有效”；通过既有 preflight/delivery 强制点实施，模块返回理由与证据引用，不重做 Fabric allow/deny 规则。
- 设计现有凭证/回执的兼容包装与恢复：运行时版本、策略/规则版本、artifact hash、有效期和撤销；禁止新增第二套任务完成状态库。
- 观测失败保持现有业务行为；正式 enforce 范围遇到关键证据缺失或不可验证时阻断相应动作并允许人工处理，两种模式不能混用故障策略。
- 用跨入口反例验证：替换内容、旧回执重放、跨租户、审批撤销、缺失验证器、重启后延迟发送；测量拦下的真实缺陷和误阻断。
- 输出：内部边界 ADR、调用图/旁路清单、反例验证、模式范围/回退与误阻断报告。
- G5：受控入口关键约束不可绕过；业务有效路径可用；没有新调度器/重复决策器；scaffold/独立部署声明维持事实，仅对实证范围报告 enforce。

## WP-09 经验归因与统计可信度

- 优先级 P0；依赖 WP-00、WP-01；角色：评价负责人；估算 3–4 日。
- 复用 pattern/capsule/learning asset 与 invocation，分开记录“可用/选中/读取/实际工具使用/结果贡献”；不可归因的 prompt-only 经验标记 unknown。
- 追踪 Effect/Evaluation/Promotion 与完成账本的唯一事实源、生产 storage provider、审计和保护指标采集；不使用测试内存 store 替代生产持久化证明。
- 盘点所有 confidence 消费者和 UI；区分候选启发式分数、统计显著性、区间与业务收益，制定版本化兼容迁移，不全局替换字段名破坏历史合同。
- 冻结主指标、分母、最小有意义提升、保护指标、样本量计算、分组随机化单位、分层方法和停止规则；小样本/全成功/全失败、聚类相关、缺失与重复事件有明确处理。
- 当前两比例检验分数不能称改进概率；顺序观察采用预定检查点或审定的序贯方法，多候选比较需处理误判累积。
- 明确经验胶囊如何映射已有 Surface；现有仅支持两个 Phase1 surface 时，新类别需先补评审后的验证器/指标合同，不能复用一个通用 promote 绕过检查。
- 输出：指标字典、归因/字段迁移方案、统计方法与固定输入测试、数据质量仪表和指标 lineage。
- G6-A：关键指标可由事实重算；分母不可丢失败任务；不能从 invocation 成功或资产读取直接晋升经验。

## WP-10 经验收益对照实验

- 优先级 P0；依赖 WP-09；真实实验另依赖对应交付/恢复门槛 WP-02/03/07/08；角色：评价与业务验收负责人；估算 3–4 日，加样本观察期。
- 对同模型与冻结版本设置无候选经验的对照和候选经验组；必要时加入“已有经验”组辨别增量收益。真实执行有副作用时不得双跑同一业务动作。
- 数据分为候选生成、验证、最终保留集；去重相似任务，防止同任务多轮重试算多个独立样本；按组/租户隔离共享记忆避免污染。
- 先隔离回放，再影子，再授权试点；模型/政策变化暂停归因或分层重建实验，不混合不同版本比较。
- 主指标建议一次交付通过率，辅以成功交付总成本、人工修订时间、接管率、复发率；低成本不通过丢弃困难任务获得。
- 结果必须允许 improved/regressed/inconclusive；报告效应量和区间、样本量、保护指标、局限与复现指令，不能依赖一个固定 20 样本门槛宣称改善。
- 输出：冻结实验登记、回放数据指纹、分组与污染检查、业务验收记录、结果报告及晋升/不晋升决定。
- G6-B：独立重跑可得到相同统计结论；缺关键保护指标不晋升；若无真实业务样本，只能验收实验基础设施，业务收益继续 unknown。

## WP-11 受控自动化与综合交付

- 优先级 P1；依赖 G2-H/G2-C、G3-B、G4-B、G5、G6-B；角色：集成 lander；估算 4–6 日，加观察窗。
- 先让系统自动采集、提出、离线验证和观察；候选批准继续人工。低风险范围的已批准安装/暂停/恢复需单独服务端授权、明确目标与时间窗。
- 自动暂停与自动恢复分别定义条件；安全边界事件立即停止相关扩量，恢复不能单靠时间到期或进程没报错。
- 组合演练：运行中配置变化、Gateway/worker 重启、旧 worker 回报、远端超时、指标迟到、禁用经验、关闭开关和不可逆业务动作。
- 输出：限定范围灰度申请、开关与模式矩阵、停止/核对/恢复 runbook、综合证据包、遗留清单和下一期入口退役计划。
- G7：运行中动作归属不改变；kill switch 可测；未知副作用先核对；无证据的范围不得扩量。没有收益结论时仅交可靠性成果，不宣称持续自进化已成立。

## WP-12 许可与权属审计

- 优先级 P0；依赖 WP-00 基线，可与其他代码实施并行；角色：审计执行者，法律结论由授权法律顾问负责；估算 2–4 日，加外部审阅。
- 严格执行 [许可审计方案](license-audit.md)，先盘点与证据，不修改许可政策。
- 输出：组件/源文件来源及许可清单、发布形态义务表、未知/冲突项、第三方声明缺口、商业化选择评估与法律审阅问题清单。
- GL：全部发布范围有已知或明确 unknown 状态；不能把 git author 或 MIT 文本视为全部权属证明；未审清模块不得被标为可独占许可。

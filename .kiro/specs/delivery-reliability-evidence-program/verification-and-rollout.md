# 验收、证据与发布

## 证据级别和索引

实施者为每个工作包维护 `evidence/<WP-ID>/manifest.json`。本计划未生成运行证据，目录在执行时创建；不得用本计划文字充当实测结果。

最小记录：工作包/门槛、基线与候选 SHA、脏树说明、环境与依赖版本、服务端范围和模式、数据集/规则指纹、命令、退出码、开始结束时间、日志/回执路径及内容哈希、发现、局限、评审者、决定和有效期。真实用户内容/密钥不得入库，敏感证据仅保留脱敏索引及授权存放位置。

| 等级 | 证据                                        | 允许的声明                                 |
| ---- | ------------------------------------------- | ------------------------------------------ |
| E0   | 源码/调用图/现有设计                        | 存在相应机制或假设，不能宣称运行成功       |
| E1   | 纯函数/单元/合同测试                        | 对测试输入行为满足合同                     |
| E2   | 真实 Gateway 与持久存储集成、重启和故障注入 | 指定环境入口链路可靠                       |
| E3   | 已授权生产试点、独立业务验收                | 指定生产范围可用                           |
| E4   | 冻结对照实验、业务结果与保护指标            | 指定任务分布和版本下有收益/无收益/结论不足 |

每个门槛除覆盖率外必须有负向证据；不能只以“测试全绿”取代需求覆盖。历史测试必须记录重跑 SHA；历史报告仅作参考。

## 必测矩阵

| 类别   | 必测项                                                                | 通过要求                                             |
| ------ | --------------------------------------------------------------------- | ---------------------------------------------------- |
| 责任   | 并发接收、过期批准、转移中任务变更、拒绝/失联、跨租户 actor           | 负责人唯一；未 apply 不转移；无越权变更              |
| 恢复   | 事实前后、状态投影前后、发送前后、回执前后 kill/restart               | 事实不丢；任务收敛；未知结果可查询                   |
| 幂等   | 重投、重复回执、同键异参、去重过期、旧 worker 完成                    | 无重复业务效果；过期记录不导致自动重做未知操作       |
| Fabric | allow/deny/ask/modify、scope、sandbox、资源、预算、策略撤销、循环路由 | 比较无执行；实际路径唯一；约束不放宽                 |
| 编排   | 两 worker 抢租约、旧 fencing token、父子取消、总 deadline、预算恢复   | 旧持有者不能推进；截止后不调度新动作                 |
| 交付   | 文件缺失/空/变化、规则版本变化、旧回执重放、延迟发送                  | 未经有效验证不完成；完成与送达分开计量               |
| 上下文 | 长会话、用户修正、多模态、超大工具结果、预算极小                      | 保留政策/当前任务及原子工具对；不足显式处理          |
| 经验   | 未选中、仅读取、多个经验、污染、版本漂移、过期/撤销资产               | 归因状态真实；撤销资产不进入新任务；旧任务按规则处置 |
| 统计   | 无提升、负提升、稀有事件、少样本、重复/迟到、全成/全败                | 不错误晋升；未知不记作零；方法及区间含义正确         |
| 约束   | 模块异常、sink 异常、旁路入口、篡改证据、权限撤销                     | shadow 不改变业务；enforce 范围拒绝不可验证动作      |

所有“零重复/零越权”是该证据集观察结论，不是对无限运行的数学保证。安全关键反例出现一次即阻断对应范围扩大，先保留事实并排查。

## 指标合同与初始门槛

- 主指标：预先冻结的一次交付通过率。分母来自合法进入试点队列的任务 cohort，拒绝/取消/超时分别报告，不能事后更换分母。
- 成本：每个成功验收任务分摊 cohort 的全部模型、工具、重试及失败成本；另报告人工修订成本。不能只算成功 attempt。
- 可靠性：恢复完成率、未知副作用积压与年龄、重复业务效果、交接耗时、人工接管和回执丢失。
- 保护指标：跨租户污染、安全事件、误阻断、交付失败、人工接管、p95 延迟、总成本；关键保护指标缺失阻断晋升。
- 数据质量：结果缺失/迟到、归因未知、重复事件、不同版本混入、原始事实与聚合差异。
- 固定反例集：必须全部通过；经验生成集与保留评测集不可混用。
- 试点扩量业务门槛由 WP-00/WP-09 按业务风险冻结。可提议成功率提升至少 5 个百分点，或质量不劣且成功交付成本降低至少 10%；这些仅是谈判起点，未冻结前不得当实际放行值。
- 主指标达到最小有意义效应并有适当区间支持，保护指标不超过预定容忍值。以收益为目标不能仅凭“不显著变差”宣称改进。
- `minimumSampleSize=20` 和旧 confidence 阈值不自动沿用；样本量按基线、效应、方法和相关性计算。达不到样本要求保持 inconclusive。

## 命令与测试执行原则

以当前 package scripts 为准，先读取再运行；下面 scoped Vitest 命令仅为现有文件的初始验证例子，不代表涵盖新增实现：

```bash
OPENBOT_TEST_PROFILE=low OPENBOT_TEST_SERIAL_GATEWAY=1 pnpm exec vitest run src/gateway/collaboration-learning/handoff-contract-entry.test.ts src/fabric/parity.test.ts
pnpm --dir packages/evolution-core test
pnpm tsgo
pnpm check
```

各工作包先跑自己覆盖的回归与集成；缺依赖按仓库规则安装后重试。修改运行逻辑推送前按仓库要求运行测试；涉及懒加载/模块边界需 `pnpm build` 且无 ineffective dynamic import 警告。worker 数不得超过 16。不能因共享树其他任务失败而修改他人文件，应记录首个错误和归属。

运行 build 前遵守新鲜 main 基线门槛；build 如覆盖了本机实际 Gateway 使用的 dist，按仓库规则重启并验证服务。不要仅为文档计划运行应用 build。本计划自身只需路径、链接、格式、归属与完整性验证。

## 灰度与停止

1. 固定回放与故障夹具：无客户外部写入，达到 E2。
2. 内部授权试点：按工具/租户/组名单限制，达到 E3；实际 scope resolver 不支持细粒度时先补能力，不用全局 flag 代替。
3. 有限客户试点：先冻结基线 cohort、版本、数据规则和保护阈值，设置有效期及人工值守。
4. 扩量：按业务特征扩大，不按一个全局百分比掩盖不受支持工具；每步重验适用范围。
5. 默认启用：以入口迁移覆盖和长期观察为依据，保留范围外 legacy 清单；不在本计划中预先承诺日期。

停止触发：任何关键安全反例、重复业务效果、责任丢失、过期授权执行、保护阈值超限或关键观测失效。shadow 比较错误只关闭比较；enforce 无法校验关键约束时停止对应动作。不可把控制面出错当成允许执行。

撤回程序：停止新动作进入候选路径→保留动作/幂等/责任事实→冻结并核对 in-flight→完成可安全排空的只读步骤→未知写操作人工核对→切回已验证路径仅处理新动作→复核指标和恢复范围。关闭 flag 不自动取消远端业务，也不清除去重记录。

## 合并与生产交付

- 绿点小步提交，使用 `scripts/committer`，每个提交带 Task/Agent trailers。共享热点只有归属已明确的 lander 提交。
- 不直接提交到远端 main；PR target 为 main，合并按 `/reviewpr`、`/landpr` 及当前仓库规范。方案通过不代表生产变更已批准。
- 不以旧规则里“CI 暂不可用”的描述代替检查当前 CI 状态；未完成检查真实报告，不伪造通过。
- 生产候选必须为 freshly fetched origin/main，干净构建，读取实际运行容器 build-info 验证 LIVE，运行 forward-only 和 delivery-alignment 门槛并核验 UI/Gateway 两部分。
- 发布前读取仓库 release 文档；发布记录进入既有 RELEASE_RECORD 和外部权威 ledger，不新建本仓库 releases.jsonl。
- 回退运行时配置/经验版本与源码部署分开；源码修复遵循主干前进，通过新提交实现，不把旧镜像切换当成已获批准的向后部署。

## 验收签字

执行者提交证据；业务负责人判定业务验收；架构评审确认唯一职责/无平行状态机；安全评审确认身份、租户、审批及副作用；统计评审确认实验方法；发布负责人确认生产门槛；法律顾问审阅许可结论。角色可以由人指定兼任，但候选生产者不得单独证明并批准自己的收益。

每个决定记录 reviewer、SHA、证据摘要和范围；需要新的安全/业务授权时提交具体变更、影响和撤回方案，不能让用户批准空泛方案。

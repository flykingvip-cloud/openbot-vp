# 咨询报告信息设计（通用）

> 当 PDF 是**汇报 / 内部交流 / 申报 / 研究报告 / 评审**材料时，必须先按本系统做**信息设计**，再做排版。
> 目标不是把长文塞进页面，而是把判断做成别人能拿去交流、评审、传播的知识产品。

本文件不绑定任何产品、品牌或组织叙事。示例可替换为当前任务的行业与命题。

## 0. 核心判断：从「文字驱动版式」到「观点驱动版式」

|          | 文字驱动版式（❌） | 观点驱动版式（✅）            |
| -------- | ------------------ | ----------------------------- |
| 组织单位 | 章节 / 段落        | 一页一个核心观点              |
| 页面职责 | 承载完整文章       | 视觉化一个判断                |
| 排版规则 | 标题 → 正文 → 加粗 | 观点 → 论证 → 证据模型 → 补充 |
| 读者体验 | 需要阅读才能理解   | 3 秒抓住观点                  |

**铁律：`1 页 = 1 个核心观点 + 1 个视觉锚点 + ≤3 组辅助信息`**

一页不允许承担一篇完整文章。内容多，就拆页，而不是缩字号、压行距。

## 1. 四层信息层级（替代 标题→正文→加粗）

```
Level 1｜观点    整页只能有一个核心观点，做大字处理
                 例：该市场应先做渠道试点，再铺开全国
Level 2｜论证    一句话解释为什么
                 例：需求已验证，但履约能力还撑不住全面铺开
Level 3｜证据/模型  用图形表达，而不是文字
                 例：试点城 × 产能 × 回款周期
Level 4｜补充信息  正文、案例、解释放在最后，字号最小
```

写作顺序永远从上往下：**先抽出 Level 1，再写 Level 2，再决定 Level 3 用什么图，最后才放 Level 4。**

## 2. 版式模式（两种场景不要混用）

| 模式                  | 页面              | 适合                                       |
| --------------------- | ----------------- | ------------------------------------------ |
| **Report Mode**       | A4 竖版 595×842pt | 申报材料、研究报告、内部交流、打印、发 PDF |
| **Presentation Mode** | 16:9 横版         | 现场演讲、评审汇报                         |

不要用同一套排版逻辑兼容两种场景。Report Mode 用 A4 竖版（除非用户明确要横版）。只要 PPTX、不要 PDF 时，走 cyber-ppt，不要用本技能硬排演示稿。

## 3. 设计 Token（全局唯一，不得每页随意变）

### Typography

- 字体族：中文字体 1 套 + 英文字体 1 套 + 数字字体 1 套，**全篇不换**。
- 层级字号（可按版面微调，但**比例必须稳定**）：
  - H1 观点大字：28–36pt
  - H2 小标题：18–24pt
  - Body 正文：10.5–12pt
  - Caption 注释：8–9pt

### Color

- **90% 中性色 + 10% 强调色**。
- 主色：黑 / 深灰；强调色：品牌色**只有一个**（用委托方或文档指定色；未指定则用一条克制的强调色）；辅助色：浅灰。
- **禁止每个章节换一种颜色。**

### Grid

- 12 栏网格；正文行宽控制在 **60–75 字符/行**，禁止超长横向文字块。

### Spacing

- 统一 8pt 间距系统：`8 / 16 / 24 / 32 / 48 / 64`。
- 标题、卡片、段落、图形之间的间距都从这套值里取。

## 4. 标准页面模板（组件库）

生成时优先套用这些组件，而不是自由排版。括号内示例可换成当前命题。

### 4.1 封面（设计化，非信息罗列）

```
大标题（可断行，一句话说清议题）
副标题（一句话定位：对象 / 范围 / 时段）
一个核心视觉（一条克制的问题或路径，如 诊断 → 方案 → 试点）
底部：委托方或品牌名 + 汇报人 + 时间
```

### 4.2 目录页 = 论证地图（不是目录文字墙）

先给一条主线，再列章节。例：

```
主线：问题界定 → 根因 → 选项 → 建议与节奏
01｜背景与范围
02｜我们发现了什么
03｜判断与取舍
04｜怎么落地
```

### 4.3 资产卡（三栏并列，不是上下堆叠）

按当前材料选三组并列概念，例如：

```
事实              判断              动作
已验证的数据       我们因此认为       下一步谁做什么
```

### 4.4 Framework Page（模型页）

```
一个中心模型（图形）
+ 一句结论
+ 一个 Before / After（如有）
```

例：「进入该业务要同时具备四个条件」→ 四个条件做成一张图 → 底部一句结论。

### 4.5 Before / After 双栏对比

```
BEFORE                 ｜  AFTER
现状怎么运转            ｜  建议之后怎么运转
            中间一个巨大的 ↑
        一句话点出变化的本质
```

### 4.6 双角色或双视角（左右双栏）

用于任何需要对照的两方（甲方 / 乙方、总部 / 一线、业务 / 风控），不要写成固定岗位故事。

```
视角 A            ｜  视角 B
他们要什么         ｜  他们要什么
约束是什么         ｜  约束是什么
        中间：双方必须对齐的一件事
        底部一句：合作或决策规则
```

### 4.7 大字观点页（3 秒抓住）

```
一句真正要被记住的判断

必要时用 2–3 句解释，不放正文大段
```

### 4.8 视觉高潮页（大数字）

```
一句结论
        关键数字 A   ↓   关键数字 B
左侧含义                 右侧含义
```

数字必须来自当前材料，禁止编造规模或编造组织叙事。

### 4.9 能力或路径页（不是功能清单）

```
一句话定位
一条从输入到结果的链路（用当前项目的真实步骤）
最终结果：用一句话写清「做成之后是什么」
```

### 4.10 结尾（留白）

```
回收本篇唯一主线
一句可带走的原则
大量留白 + 委托方或品牌名
```

## 5. 自动减法规则（硬规则，生成时逐条自检）

| #      | 触发条件                    | 动作                                                            |
| ------ | --------------------------- | --------------------------------------------------------------- |
| Rule 1 | 一页正文超过 500 字         | 自动考虑拆页                                                    |
| Rule 2 | 出现 3 个以上并列概念       | 自动转卡片 / 矩阵                                               |
| Rule 3 | 出现 `A → B → C → D`        | 自动转流程图 / 时间轴 / 演进箭头                                |
| Rule 4 | 出现 Before / After         | 自动使用双栏对比                                                |
| Rule 5 | 出现「核心观点 / 核心命题」 | 自动放大处理                                                    |
| Rule 6 | 一句话能表达的              | 不允许用一段话表达                                              |
| Rule 7 | 每页必须有视觉锚点          | 锚点 = 大数字 / 核心模型 / 流程 / 引言 / 对比 / 矩阵 / 关键结论 |
| Rule 8 | 连续两页不能完全相同版式    | 版式结构可变，但**设计语言必须一致**                            |

### 5.1 流程自动识别规则

检测到正文里存在箭头链 / 步骤序列时，**优先生成横向流程图 / 时间轴 / 演进箭头**，不要让流程留在段落里。流程本身就是页面的主视觉。

## 6. 四层工作流（本系统在 nano-pdf 中的位置）

```
① Content Architecture   识别内容结构：抽出观点、论证、证据、补充
        ↓
② Information Design     把文字转成模型、流程、卡片、矩阵、对比
        ↓
③ Editorial Design       控制字体、网格、层级、留白（本文件 §2–4）
        ↓
④ Print Production       PDF 生成、字体嵌入、分页、安全边距、渲图验收
                         （见 SKILL.md 与 create-render.md）
```

**先完成 ①② 再进入 ③④。** 跳过信息设计直接排版 = 回到「文字驱动版式」。

## 7. 高频组件（按材料选用，不预设故事）

咨询材料里反复出现的是结构，不是某一家的口号。优先识别并套用：

1. **条件模型**：做成这件事要同时满足的 N 个条件（Framework Page）
2. **规模或幅度**：用真实数字做前后对照（视觉高潮页）
3. **并列资产**：三类以上并列项做成卡片或矩阵（资产卡）
4. **双视角**：两个角色 / 两套约束对照（双栏）
5. **价值或路径迁移**：从旧状态到新状态的一句话演进（大字观点页 / 箭头）

禁止把上述结构填成固定的产品口号或组织变革故事。没有对应事实就不用该组件。

## 8. 交付前自检清单

- [ ] 每页是否只有一个核心观点？
- [ ] 每页是否有视觉锚点？
- [ ] 是否所有 `A→B→C` 都已图形化，而非留在段落？
- [ ] 并列概念（≥3）是否已卡片化 / 矩阵化？
- [ ] Before/After 是否用了双栏对比？
- [ ] 是否有「大字观点页」，数字页是否只用了材料里的数？
- [ ] 单页正文是否 ≤500 字？
- [ ] 字体 / 颜色 / 间距 token 是否全篇一致？
- [ ] 连续两页版式是否不同但设计语言一致？
- [ ] 结尾是否留白？
- [ ] 全文是否未写入与当前委托无关的品牌或组织叙事？

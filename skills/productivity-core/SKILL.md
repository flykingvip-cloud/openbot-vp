# productivity-core（生产力与项目闭环）

把「今天做什么」与「项目怎么推进」统一到可归属、可验收的工作闭环。日简报、项目计划、任务排序三选一或多选并用；排程/登记用 spreadsheets；章程/报告用 documents。

## 概述

- **日工作简报**：承诺、截止、阻塞与新信息 → 今日优先级。
- **项目管理**：结果 → 交付物 → 里程碑/WBS → RAID → 状态与恢复。
- **任务排序**：按影响、紧急、代价、依赖、延迟成本排序；区分已确认承诺与提案。
- 勿臆造负责人或日期；忙碌≠完成。

## 前置

1. 确认目标类型：今日简报 / 项目规划跟踪 / 纯优先级排序。
2. 收集承诺清单、硬期限、干系人、预算/人力、成功标准与已知风险。
3. 约定状态枚举与汇报频率；若存在 `project-shepherd`，按 MERGE-PLAN 单权威。
4. 选定载体：计划表 xlsx、章程 md/docx、RAID 表、日简报 md。

## 流程

### A. 日工作简报

1. 列出已确认承诺 vs 提案；缺主责/日期标「未指派/未定期」。
2. 按延迟成本 × 影响排序；标阻塞与可并行项。
3. 输出「今日必做 / 可推 / 需决策」三栏，附一句健康判断。

### B. 项目管理

1. **结果陈述**：一句话目标 + 非目标。
2. **拆交付物**：可验收；拒绝纯「开会/跟进」当交付物。
3. **里程碑与 WBS**：准入/准出、主责、目标日、依赖、验收。
4. **关键路径**：最长依赖链与无主责项（无主责不得标进行中）。
5. **RAID**：风险含可能性/影响/缓解/触发器；假设可验证；问题有关闭日；依赖有需要日。
6. **基线与变更**：冻结关键日期；变更记原因/影响/批准人。
7. **状态汇报**：健康（绿/黄/红）→ 相对上次变化 → 待决 → 阻塞 → 近程里程碑 → 纠正动作。
8. **恢复计划**（黄/红）：减范围 / 加资源 / 移日期，写清权衡，勿只写「加强跟进」。

### C. 任务排序

1. 建字段：影响、紧急、努力、依赖、延迟成本、确认状态。
2. 先排已确认承诺；提案单独区，避免挤占关键路径。
3. 输出排序表 + 取舍理由（为何不做某项）。

## 输出

```text
output/productivity/<id>/
  daily-brief.md          # 可选
  charter.md              # 项目
  plan.xlsx               # 或 plan.md
  raid.md
  status/<date>.md
  prioritization.md       # 或 .xlsx
  change-log.md
```

任务表列：`ID | 交付物/任务 | 负责人 | 开始 | 目标日 | 依赖 | 状态 | 验收 | 备注`。

健康建议：无主责关键任务或关键路径延误未缓解 → 至少黄；硬期限不可达且无批准变更 → 红。

## 边界

- **做**：日简报、范围/WBS、里程碑、RAID、状态与恢复、优先级表。
- **不做**：臆造完成度；未授权改外部 PM 工具；替代会议技能写纪要。
- **重叠**：`project-shepherd` 并存时按 MERGE-PLAN；本技能已吸收并取代 merges 中的 `project-management`。
- **相邻**：会议行动 → meeting-communication-core；战略选项 → strategy-core；例行刷新 → office-automation-core。
- **警告：** 勿使用 Codex artifact 协议 / `openai.yaml`；交付用工作区文件。勿把密钥写入技能正文。

## 触发样例

- 「根据日历和待办写今日工作简报」
- 「把需求拆成里程碑和任务表，标负责人」
- 「写项目周报，突出阻塞和待决决策」
- 「只能做三件事，按延迟成本排序并说明放弃项」

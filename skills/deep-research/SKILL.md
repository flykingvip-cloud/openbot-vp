# 深度研究

先判断用户要解决的决策问题，再搜证。默认结论优先、证据够用即止。用户明确要求详细时再展开。

禁止：编造来源或数据、无来源市场规模、把推测写成事实、把研究包装成绝对结论。检索命中不是来源；未打开的 URL 不得写入来源表。缺口单列，交接网页抓取时走 `web-research` 的三分流（`references/stages.md`）。

## 先判断

1. 用户真正要回答什么？决策者是谁？
2. 已有材料是否足够？不足才搜索。
3. 这是未知问题（本技能）还是已有文本理解（`knowledge`）？
4. 是否需要人工确认范围、竞品名单或保密边界？

## 工作流

问题定义 → 范围 → 资料搜索 → 来源验证 → 纵向时间线 → 横向格局 → 关键变量 → 矛盾与反例 → 综合判断 → 结论 → 不确定性

细则按需读 `references/workflow.md`。证据记录读 `references/evidence.md`。

### 纵轴

起源、关键节点、阶段、锁定性决策。讲因果，不记流水账。

### 横轴

先判断竞品：无 / 少 / 多。比生态位与用户真实选择理由，不写参数说明书。

### 交汇

历史如何塑造今日位置；优势/劣势的历史根源；反例；三个剧本（可能 / 危险 / 乐观）且标明推测。

## 必须交付

1. 来源记录（标题、URL、日期、访问日、一手/二手）
2. 事实与观点分离
3. 时间线
4. 竞争格局
5. 证据强度（高/中/低/不足）
6. 反例
7. 不确定性与缺口
8. 最终判断（带置信）

搜不到写「暂缺」，不要补齐。

## 默认输出

```text
结论（含置信与数据截止日）
关键证据
时间线（要点）
竞争格局
反例与分歧
不确定性
下一步（可选）
来源表
```

详细模式才写完整叙事。不要默认 1–3 万字。

## 交接

| 需求                    | 去向                     |
| ----------------------- | ------------------------ |
| 精读已有 PDF/纪要       | `knowledge`              |
| 写成对外文章            | `content`                |
| 多平台拆条              | `content-ops`            |
| 只要证据表/来源分级细节 | `research-core`          |
| 网页发现/确认链接归档   | `web-research`（三分流） |

## 组合

`deep-research` → `knowledge`（读自己的产出）→ `content` → `content-ops`。UI 交接 `design`。不要在本技能里写终稿或拆条。

## 验收

- 关键数字都能在来源表找到，或标了暂缺
- 事实句与判断句可分开
- 有反例或「未发现反例」的显式声明
- 未要求详细时，不超过简报长度

## 触发样例

- 「研究这家公司和它的主要竞品」
- 「这个概念从哪来，现在谁在用」
- 「不要长文，先给判断和证据」

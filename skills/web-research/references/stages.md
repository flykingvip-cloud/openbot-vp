# 调研三分流

触发本技能之后，先选阶段，再动手。禁止把搜索命中、已读正文、媒体落盘挤在同一步。

## 三阶段

| 阶段 | 做什么                                                         | 不做什么                                  | 产出                                |
| ---- | -------------------------------------------------------------- | ----------------------------------------- | ----------------------------------- |
| 发现 | 出候选：标题、URL、平台、日期、一句限制                        | 不 `web_fetch` 正文当已归档；不下载音视频 | `candidates.md`                     |
| 归档 | 只处理**当前任务已确认**的 URL（用户点名，或发现清单里勾过的） | 不顺着搜索结果自动抓完全部；不覆盖旧目录  | `sources.md` 只含实际打开的页       |
| 转写 | 工作区里**已有**音视频文件才交接 ASR                           | 不为了转写去搜平台并下载                  | 转写定本路径；交接 `openai-whisper` |

默认：只要判断/简报 → 发现 + 对少量官方 URL 归档。用户没说「保存原文 / 下载视频 / 出字幕」就停在发现或有限归档。

## 硬规则

1. **检索不等于下载。** `web_search` 命中不得写入 `sources.md`，只能进 `candidates.md`，状态=`unfetched`。
2. **未打开的 URL 不得声称已阅读**（与 SKILL 正文一致）。
3. **后端不静默替换。** 需要小红书/抖音/X 原生页时，写明「本会话只有通用 `web_fetch`，未做平台适配」，不要假装已用平台接口。
4. **缺口单列。** `report.md` 必须有「未核实 / 未归档 / 未转写」。不得用推测补齐。
5. **归档不覆盖。** 同一 URL 再跑写入 `output/research/<topic-id>/archive/run-N/`，不改旧 run。

## 何时读

- 用户要调研/比较/读网页，且可能继续「把这些链接存下来」或「转成字幕」
- 搜索成功后，模型准备对一串结果调用 `web_fetch` 或下载

## 交接

| 下一需求                 | 去向                                               |
| ------------------------ | -------------------------------------------------- |
| 主张—证据表、来源分级    | `research-core`（`sources.md` 只能用归档过的来源） |
| 战略横纵                 | `deep-research`（同样遵守检索≠归档）               |
| 已知链接当运营素材 / 3:4 | `content-ops`                                      |
| 只要文本或 SRT           | `openai-whisper`（先读其 routing；禁止换家重跑）   |
| 单页去噪                 | `defuddle`（仍算归档，记入 `sources.md`）          |

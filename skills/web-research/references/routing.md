# 网页调研路由（意图 + 时效性 + 用户要求）

识别用户意图后按三个维度决定是否自动触发本技能，不要只靠「调研 / 搜索」关键词。

| 维度       | 问什么                                            | 触发倾向                                |
| ---------- | ------------------------------------------------- | --------------------------------------- |
| 意图       | 用户要调研、比较、读网页，还是改写/解释已有材料？ | 调研 / 比较 / 读指定页 → 是             |
| 信息时效性 | 答案会不会很快过时？                              | 当前价格、最新政策、行业动态 → 是       |
| 用户要求   | 必须外出取证，还是材料已经在会话里？              | 要外部网页 → 是；已有文本/上传文档 → 否 |

## 触发表

| 触发场景                   | 是否调用 `web-research` | 判断依据                  |
| -------------------------- | ----------------------- | ------------------------- |
| 用户明确说「调研」「研究」 | 是                      | 明确的调研意图            |
| 比较多个产品当前价格       | 是                      | 外部、可能变化的信息      |
| 问最新政策、行业动态       | 是                      | 时效性要求                |
| 阅读指定网页并分析         | 是                      | 需要网页内容读取          |
| 只要求改写已提供的文本     | 否                      | 任务可基于已有内容完成    |
| 问稳定的基础知识           | 通常否                  | 未必需要联网              |
| 分析自己上传的文档         | 否                      | 走 `knowledge` / 文档分析 |

上传文档同时又要「对比网上最新口径」时，文档分析与本技能可先后做，不要互相吞掉。

已经决定调用本技能后，还要按 `references/stages.md` 选阶段：默认只做发现；用户点名链接才归档；有本地媒体才转写。禁止把搜索结果自动变成下载。

## 交接

- 只要证据表 / 来源分级 → `research-core`
- 战略纵深、横纵格局 → `deep-research`
- 金融报价与财报 → `finance-research`
- 单页去噪 → `defuddle`
- 只打开多平台页面 → `agent-reach`

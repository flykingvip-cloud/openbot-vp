# OpenBot 回写

公众号在 OpenBot 里是**数字身份**，不是聊天渠道。企业身份与个人身份各有一份店，字段相同：AppID、AppSecret、出口 IP 提示。没有 Token 输入。

## 选店

| 用户说                             | 写入                                |
| ---------------------------------- | ----------------------------------- |
| 企业身份 / 系统设置 / 租户公众号   | `operational_identity`（企业）      |
| 个人设置 / 我的授权 / 员工自己的号 | `user_operational_identity`（个人） |

同一 AppID 不要在两边重复绑成两个「当前号」还不分显示名。授权给机器人是下一步（enrollment / grant），不是本技能的写入字段。
个人店智能化编排入口：`oi-bind-wechat-official`（固定 personal；仍经 `user-operational-identity.credentials.bind`）。

## 写入字段

| 字段      | 必填     | 来源                                |
| --------- | -------- | ----------------------------------- |
| AppID     | 是       | 控制台基本配置 / 开发信息           |
| AppSecret | 是       | 用户已有，或本次重置后立刻抄        |
| 显示名    | 是       | 控制台昵称或 `getaccountbasicinfo`  |
| Token     | **否**   | 不要创建、不要向用户要              |
| IP 白名单 | 在微信侧 | 工作台「出口 IP」全部写入公众号后台 |

企业注册档案只接受手动 AppID + AppSecret，没有「扫码授权」入口。

## 验收顺序

1. 保存身份（密钥进 secret store，不进聊天）。
2. 先做独立换票。企业页「测试连接」可能空点、不刷新 `lastVerify`；页上「Token 正常」是残留文案，不是要用户填 Token。
3. 换票成功后**再看**身份页 lastVerify。旧 FAILED / `40164` 不能当现状。
4. 需要证明号：只读账号资料，核对昵称 / 主体 / AppID。
5. 授权给某个数字人：走企业员工绑定或个人 grant。本技能不代替授权。
6. 「编辑凭证」若弹出 DataSource 绑定窗，关掉，不要当公众号表单。

## 现网对照（经验，不含密钥）

| 号                     | 典型店         | 曾卡在                                                                    |
| ---------------------- | -------------- | ------------------------------------------------------------------------- |
| 昵称「AI数字替身」     | 企业微信公众号 | 白名单缺第二出口 IP；密钥在开发者平台被重置未回写；lastVerify 停在旧失败  |
| 昵称「小飞鱼优才学府」 | 个人微信公众号 | 显示名没回写，店里只剩「微信公众号」；机器人会话缺 grant 被误判成凭证坏了 |

对照时只报 AppID 与昵称，不报 secret。

## 禁止

- 把 AppSecret 写进 `accessToken` 槽位还告诉用户「这是 Token」
- 用腾讯会议 Token 字段冒充公众号配置
- 未换票成功就宣称「已打通发布」
- 把 `publishId=0` 的执行失败写成凭证失败

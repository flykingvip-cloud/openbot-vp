# 公众号凭证错误

先看微信 `errcode` / `errmsg` / `rid`，再看 OpenBot `IDENTITY_*`。不要把「access_token」字样理解成「用户少填了 Token」。

## 微信侧

| 信号                                        | 真因                                     | 动作                                                                                       |
| ------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| `40164` `invalid ip … not in whitelist`     | 网关出口 IP 不在白名单                   | 把报文里的 IP **和** 工作台全部出口 IP 写入白名单，回读后再换票                            |
| `40001` `invalid credential` / `not latest` | 密钥不对，或旧 `gettoken` 缓存被并发作废 | 核对 AppSecret；清掉身份店里缓存的 accessToken；用 `stable_token` 重换。不要向用户要 Token |
| `40125` `invalid appsecret`                 | AppSecret 错或已重置未回写               | 用户同意后重置并立刻写入身份店                                                             |
| `41001` missing access_token                | 换票请求没带上系统票                     | 查绑定，不要让用户填 Token                                                                 |
| `45009` / 频控                              | 换票太勤                                 | 停手，等窗口，不要连点测试                                                                 |
| `data format error` 且 `publishId=0`        | 验收参数非法                             | **不是**凭证失败。改用换票或只读账号资料                                                   |

## OpenBot 侧

| 信号                                      | 真因                                             | 动作                                       |
| ----------------------------------------- | ------------------------------------------------ | ------------------------------------------ |
| `IDENTITY_002` 详情像校验标签而不是微信码 | 失败时把 `configReadiness` 的 **label** 当成详情 | 读同一条的 `detail`（常是 `40164`）        |
| lastVerify=FAILED 但现网换票已成功        | 测试结果没刷新                                   | 再跑一次「测试连接」/ `verify_credentials` |
| capabilities 全空、发布动作都在 missing   | 上次失败探测没重跑                               | 换票成功后重测，刷新能力清单               |
| `USER_IDENTITY_SESSION_REQUIRED`          | 机器人会话没有个人身份 grant 上下文              | 查 grant / 登录，不是公众号白名单          |
| 企业「需要员工会话 / Enterprise session」 | 企业身份没走 enrollment 回退                     | 查员工绑定，不是缺 Token                   |
| 显示名一直是「微信公众号」                | 没回写 nickName                                  | IDENTIFY 后写入显示名                      |

## 过程陷阱（已发生过）

1. **Token 语义污染**：腾讯会议要 Token；公众号不要。不要把会议 Token 或消息推送令牌填进公众号身份。
2. **只写了一个出口 IP**：工作台先显示 `A`，网关实际从 `B` 出网 → `40164` 报 `B`。
3. **控制台重置了 AppSecret，身份店还是旧的** → `40001`。
4. **用群发 / `publishId=0` 当测试** → 格式错误，误判凭证坏了。
5. **扫到用户自己的 Chrome**：隔离页一直停在登录。立刻重开隔离页，不要空等。
6. **后一张码当成登录失败**：② 开发者平台、③ AppSecret、④ IP 白名单都是新码，不要重开公众号登录页。
7. **告诉用户扫一次就结束**：新会话主路径是 2～3 次。白名单仍要改时再加一次。续做会话还在则不要重扫。
8. **信旧公众号「查看」名单**：可能缺 IP。只信开发者平台回读。
9. **在旧 IP 弹窗点确认修改**：会覆盖新平台已写入的地址。
10. **信企业页「测试连接」或「Token 正常」**：按钮可能不刷新探测；Token 是残留标签。以独立换票为准。

## 报告口径

对用户只说：哪个号、AppID、白名单是否含全部出口 IP、换票是否通过、还缺哪一步。不说 Token，不贴密钥，不贴 rid 以外的内部路径。

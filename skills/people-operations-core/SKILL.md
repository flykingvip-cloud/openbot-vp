# people-operations-core（人事运营工件）

支持可重复的人员与行政流程：把角色、里程碑、学习结果与可观察证据写成可分发草稿。中性措辞；区分直接观察与解读；最终人事判断留给授权人。

## 概述

- **入职协调**：入职前、首日权限、角色语境、干系人、学习里程碑与 owner。
- **培训材料**：学习目标、先修、示例、练习与理解验收。
- **绩效回顾草稿**：可观察结果、行为、影响、发展区与未来期望。
- 正式手册 DOCX → documents；课表/清单表 → spreadsheets；宣讲 PPT → cyber-ppt。

## 前置

1. 确认受众（新人/经理/学员）、时区与入职日、角色级别、保密要求。
2. 收集岗位说明、能力模型、既有模板；缺证据则明确「待经理补充」。
3. 约定语气（鼓励/中性）与是否可分发；敏感内容默认最小必要。
4. 明确：本技能产出草稿，不写入 HRIS、不发送绩效信，除非用户授权且环境支持。

## 流程

### A. 入职协调

1. 时间线：入职前 / Day1 / Week1 / Day30/90；每项有 owner 与验收。
2. 权限与工具清单；依赖 IT/行政的标阻塞风险。
3. 角色语境：团队目标、关键接口人、首月成功样子。
4. 输出可勾选清单 + 给经理的简短 briefing。

### B. 培训材料

1. 学习结果可检验；先修与时长写清。
2. 概念 → 示例 → 练习 → 验收题/实操。
3. 避免歧视性假设；示例用中性场景。
4. 需要幻灯时交出大纲后移交 cyber-ppt。

### C. 绩效回顾草稿

1. 只基于用户提供的观察与结果；缺证据处标「需补充」，禁止编造。
2. 结构：成果 → 行为 → 影响 → 发展区 → 下期期望。
3. 区分事实与解读；避免人格标签与受保护特征推断。
4. 经理可编辑；保留「草稿」水印语义（文件名或页眉说明）。

## 输出

```text
output/people-ops/<id>/
  onboarding-plan.md
  checklist.xlsx          # 可选
  training-outline.md
  performance-draft.md
  manager-brief.md
```

## 边界

- **做**：入职计划、培训大纲/讲义草稿、绩效沟通草稿、角色期望说明。
- **不做**：雇佣/解雇决定；编造绩效事实；推断健康/信仰等敏感属性；未授权写 HRIS 或群发。
- **相邻**：正式制度文档版式 → documents；调研外部实践 → research-core。
- **警告：** 勿使用 Codex artifact / `openai.yaml`；交付用工作区文件。注意隐私最小化。

## 触发样例

- 「给新同事做 30/90 天入职计划清单」
- 「写一份内部工具培训大纲，带练习」
- 「根据这些要点起草绩效回顾，标明缺证据处」
- 「角色期望一页纸，给经理和本人各一版语气」

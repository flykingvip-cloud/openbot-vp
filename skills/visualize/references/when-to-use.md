# 何时用 / 不用

## 用

- 机制解释：用户要「看见怎么动」
- What-if / 参数扫描：滑条、步进改变同一主视觉
- 对照：两系列/两方案并排或叠加，需点选系列
- 轻量 UI mockup：在对话里预览界面结构（非写入产品仓库）
- 地图 + 真实坐标/边界数据
- 密集分类格：一格一标识 + 选中摘要

## 不用（改走别路径）

| 信号                             | 改走                    |
| -------------------------------- | ----------------------- |
| 「写个页面进我们的 Next 项目」   | 工程实现，非本技能      |
| 「给个流程图就行」               | Mermaid                 |
| 「列个表」                       | Markdown 表             |
| 「做个看板挂到 Node」            | `canvas`                |
| 「出 PPT」                       | `cyber-ppt` 等          |
| 科学出版级静态图且用户指定工具链 | 用户指定的绘图工具/脚本 |

## 形态速查

1. **Explainer / 仿真**：最多一组紧凑控件 + 一个主视觉；默认不要摘要卡；步进只更新当前画面。
2. **图/曲线**：简单值用手写 SVG；复杂标度/图例用 D3（pinned CDN，如 `d3@7`）。坐标轴写清量与单位；系列色用 `--viz-series-1..6`。
3. **地图**：`d3-geo` 投影公开 GeoJSON/TopoJSON；勿手绘国界；空白底图不合格。
4. **Mockup**：自建产品色与字号；**不要**用通用 `.card`/`.btn` viz 工具类冒充产品 chrome。
5. **分配/占比**：堆叠或份额图；不要只给总计柱再复制一张热力。

## 构图原则

- 能交互细节就不要常驻侧栏/重复图例
- 只加用户要的控件；一种状态一种控件
- 展示解释行为所需的度量；最大值是上限不是目标
- 窄宽（约 320–736px）可堆叠；多面板并排对照时再考虑更宽布局

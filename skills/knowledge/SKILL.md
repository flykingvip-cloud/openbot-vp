# 知识处理

先理解，再压缩。只做摘要而不理解，算失败。材料不足就标明缺口，不补现场、不编实验。

## 先判断

1. 材料是否已在对话/文件里？没有就向用户要，不要改去全网调研。
2. 用户要的是压缩、结构、解释、对比，还是质疑？
3. 需要读哪几页/哪几章？先定范围再读。

## 模式

| 意图          | 模式      | 何时读                    |
| ------------- | --------- | ------------------------- |
| 缩短、要点    | summarize | 默认即可                  |
| 章节/论证骨架 | structure | `references/modes.md`     |
| 外行也能讲清  | explain   | `references/modes.md`     |
| 两份以上材料  | compare   | `references/modes.md`     |
| 找漏洞、偏差  | challenge | `references/challenge.md` |

未指定时：有材料 → summarize + 轻量 challenge；用户说「讲透/拆开」→ explain。

## 统一输出

1. 一句话结论
2. 核心观点
3. 结构
4. 关键证据
5. 重要概念
6. 逻辑关系
7. 反例/问题
8. 可迁移启示

每条能指回原文位置（页、节、引句）。区分：材料中的事实、作者观点、你的解释。

## Challenge（必须主动做这些检查）

- 作者假设
- 证据不足
- 逻辑跳跃
- 反例
- 未回答的问题
- 潜在偏差（样本、利益相关、过时）

Challenge 不是抬杠：先复述对方最强论证，再打。

## 禁区

- 用流畅故事代替原文没有的数据
- 把评测差异写成因果
- 大规模补搜后冒充「读了这份材料」
- 直接写出发文章（交接 `content`）

## 交接

| 需求                 | 去向                                          |
| -------------------- | --------------------------------------------- |
| 材料不够，要外部事实 | `deep-research`                               |
| 理解完要成稿         | `content`                                     |
| 写入/治理企业知识库  | `knowledge-gardener` / `source-lock-and-cite` |
| 只要 URL 快摘        | `summarize` CLI（若环境有）                   |

## 组合

上游可以是用户文件或 `deep-research` 报告。下游写作走 `content`，再分发走 `content-ops`。不要在本技能里做全网未知问题调研。

## 验收

- 八段都有，且能指回原文
- 指定 challenge 时，假设与反例不能为空话
- 材料没有的数字不得出现
- 读者能用自己的话复述问题与贡献

## 触发样例

- 「把这份纪要结构化」
- 「这篇论文在解决什么，证据到哪」
- 「对比这两份方案，并挑战推荐理由」

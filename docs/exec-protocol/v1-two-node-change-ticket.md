### 3.1 默认路径：经认证的 SSH 转发（方向、端点、断线恢复）

占位符（分配批准后替换，不得填入生产 22004/22005/22006 或 10.21.88.4/5/6）：

- `ISO_A_SSH_PORT` 拟用 `22014`；`ISO_B_SSH_PORT` 拟用 `22016`
- `ISO_A_USER` / `ISO_B_USER` 拟用 `openbot-iso`
- `ISO_A_KEY` / `ISO_B_KEY`：仅保存在操作人 Mac 上的隔离主机密钥（待签发）
- 跳板密钥保持现有位置：阿里云 `~/.ssh/aliyun-openbot.pem`，香港 `id_ed25519`

建议在操作人 Mac 的 SSH config 中按跳板分别指定密钥（示例，待批准后落盘，本轮不写入任何真实主机）：

```
Host aliyun-openbot-jump
  HostName 123.56.117.116
  User admin
  IdentityFile ~/.ssh/aliyun-openbot.pem
  IdentitiesOnly yes
  ForwardAgent no

Host hk-openbot-jump
  HostName 8.217.93.71
  User root
  IdentityFile ~/.ssh/id_ed25519
  ProxyJump aliyun-openbot-jump
  IdentitiesOnly yes
  ForwardAgent no

Host openbot-iso-a-prime
  HostName 103.155.77.194
  Port 22014
  User openbot-iso
  IdentityFile ~/.ssh/ISO_A_KEY
  ProxyJump hk-openbot-jump
  IdentitiesOnly yes
  ForwardAgent no
  LocalForward 127.0.0.1:28790 127.0.0.1:18790
  RemoteForward 127.0.0.1:18791 127.0.0.1:28791

Host openbot-iso-b-prime
  HostName 103.155.77.194
  Port 22016
  User openbot-iso
  IdentityFile ~/.ssh/ISO_B_KEY
  ProxyJump hk-openbot-jump
  IdentitiesOnly yes
  ForwardAgent no
  LocalForward 127.0.0.1:28791 127.0.0.1:18790
```

**连接方向与端点**

1. B′ 协议进程在 B′ 本机监听 `127.0.0.1:18790`。
2. 操作人 Mac 建立到 B′ 的认证 SSH，并把 Mac 本机 `127.0.0.1:28791` 转到 B′ `127.0.0.1:18790`。
3. 操作人 Mac 建立到 A′ 的认证 SSH，并把 A′ 本机 `127.0.0.1:18791` 远程转发到 Mac `127.0.0.1:28791`（即 B′ 回环）。
4. A′ 协议进程连接 `http://127.0.0.1:18791`（`OPENBOT_EXEC_PROTOCOL_B_URL`），不直连 B′ 内网或公网端口。
5. 操作人管理 A′：经同一跳板把 Mac `127.0.0.1:28790` 转到 A′ `127.0.0.1:18790`。

等价命令模板（密钥均在 Mac，不启用 agent forwarding）：

```
ssh -N -o ForwardAgent=no -o IdentitiesOnly=yes \
  -L 127.0.0.1:28791:127.0.0.1:18790 \
  openbot-iso-b-prime

ssh -N -o ForwardAgent=no -o IdentitiesOnly=yes \
  -L 127.0.0.1:28790:127.0.0.1:18790 \
  -R 127.0.0.1:18791:127.0.0.1:28791 \
  openbot-iso-a-prime
```

**断线恢复（只重启隧道，不重启协议进程，不在生产机上自动拉起任何进程）**

- 检测：A′ 对 B′ 的 apply 返回 `EXEC_UNREACHABLE`；A′ 记录保持 `pending_sync`；调度器可发出 `pending_sync_stale` / 恢复窗口告警。管理端 `ssh -O check` 或本机 `28790/28791` 连接失败亦可确认隧道已断。
- A′ 调度器继续持有持久 `pending_sync`，按第 5.7 节退避重试；**不要**为了恢复同步而重启 A′ 或 B′ 协议进程，也**不要**人工调用 `resumePendingReconcileSyncs()` 作为默认恢复手段。
- 恢复：仅在操作人 Mac 上重新执行上述 `ssh -N -L/-R`（或 `ssh -O exit` 后再拉起同一转发）。隧道恢复后，调度器在当前突发间隔（最长 15s）加一个 tick 内自动继续同步。
- 禁止在香港 LIVE、生产 A/B/C 或 soak 上配置自动重启、autossh 或防火墙变更。本单也不在本轮启用任何生产主机上的自动拉起。

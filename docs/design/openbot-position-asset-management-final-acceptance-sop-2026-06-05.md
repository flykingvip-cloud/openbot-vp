# OpenBot 岗位资产管理一期最终验收 SOP（2026-06-05）

关联文档：

- `docs/design/openbot-position-asset-management-plan-2026-06-04.md`
- `docs/design/openbot-position-asset-management-work-breakdown-2026-06-04.md`

## 文档定位

本文用于把岗位资产管理一期的最终验收动作整理成一份可直接执行的 SOP。

适用对象：

- 联调负责人
- 测试负责人
- 企业端运营验收同学

本文只覆盖一期范围：

1. `P0` `seatId` 精确继任
2. `P0.5` 审计体系
3. `P1` `seatOffer` 深链接岗位确认
4. `P2` 资产继承策略

不覆盖下一阶段范围：

- `Tenant / Space / Seat` 完整权限协作模型
- 多岗位 `primary / secondary` 消费规则
- 完整 Ownership / Permission 分层

## 前置条件

执行前必须确认以下条件已满足：

1. 当前分支包含岗位资产管理一期最新实现。
2. 本地聚焦测试已通过。
3. 公网环境已配置 `OPENBOT_PUBLIC_APP_BASE_URL`。
4. 平台登录与企业端控制台可正常打开。
5. 岗位确认邮件与激活邮件发送链路可用。

建议先保留以下材料：

1. 控制台截图目录
2. 浏览器录屏
3. 公网邮件截图
4. 运行日志与接口响应快照

## 验收数据准备

建议准备一个独立企业租户，例如 `Acme Acceptance`。

建议在该租户下准备以下岗位与成员：

1. 三个同名岗位：
   - `销售经理 / 华东`
   - `销售经理 / 华南`
   - `销售经理 / KA`
2. 一个空岗岗位：
   - `销售助理`
3. 一个已在岗岗位：
   - `运营负责人`
4. 一个待交接岗位：
   - `财务负责人`

建议准备以下账号：

1. 企业管理员 `owner@example.com`
2. 已注册成员 `successor@example.com`
3. 未注册成员 `newhire@example.com`

## A. 研发验证

### A1. `seatId` 精确继任

步骤：

1. 在同名岗位场景中，对 `销售经理 / 华南` 发起新员工任命。
2. 请求中显式使用目标 `seatId`。
3. 完成激活后检查成员当前岗位。

通过标准：

1. 新员工最终绑定到指定 `seatId`。
2. 另外两个同名岗位不受影响。
3. 任命发出后岗位状态为 `assigned`。
4. 激活完成后岗位状态变为 `occupied`。

留证建议：

1. 任命前岗位列表截图
2. 任命后岗位状态截图
3. 激活完成后岗位状态截图

### A2. 已注册员工岗位确认

步骤：

1. 对已注册成员 `successor@example.com` 发起岗位确认。
2. 管理端选择“完整继承”发送岗位确认。
3. 成员登录后进入岗位确认区并点击接受。

通过标准：

1. 员工接受前岗位状态为 `assigned`。
2. 员工接受后 `currentSeat` 生效。
3. `pendingOffer` 清空。
4. 员工最终落到指定 `seatId`。

### A3. `assignmentId` 全链回溯

步骤：

1. 在管理端记录岗位任命摘要中的 `assignmentId`。
2. 发送岗位确认或激活。
3. 完成接受。
4. 核对审计日志与控制台摘要。

通过标准：

1. 同一任命在发出、提醒、接受阶段都能关联同一个 `assignmentId`。
2. 新员工任命显示 `assignmentType = new_hire`。
3. 已注册员工确认显示 `assignmentType = internal`。

### A4. 自定义继承

步骤：

1. 对某个岗位发起岗位确认。
2. 切换到“自定义继承”。
3. 只勾选部分机器人、部分协作空间，并选择是否沿用 memory。
4. 员工接受岗位。

通过标准：

1. 仅勾选资产进入最终岗位结果。
2. 未勾选资产不进入结果。
3. memory 行为与勾选项一致。

### A5. connector 重授权

步骤：

1. 对含 connector profile 的岗位发起交接。
2. 发送岗位确认并完成接受。
3. 检查交接后 connector 行为。

通过标准：

1. connector profile 继续可见。
2. credential 保持重授权状态。
3. 审计中可找到对应重授权事件。

## B. 联调验证

### B1. 公网投递与打开

步骤：

1. 发送岗位确认邮件。
2. 在公网邮箱中打开邮件。
3. 点击确认链接。

通过标准：

1. 链接域名为公网基址。
2. 点击后可直接打开企业登录页。
3. 不再落到通用注册页。

留证建议：

1. 邮件截图
2. 链接地址截图
3. 打开后的页面截图

### B2. 登录回跳

步骤：

1. 员工从岗位确认邮件进入登录页。
2. 完成登录。

通过标准：

1. 登录后自动进入个人设置中的岗位确认区。
2. URL 或页面上下文保留 `seatOffer` 语义。

### B3. 接受结果

步骤：

1. 员工在岗位确认区点击接受。
2. 刷新页面。

通过标准：

1. `pendingOffer` 消失。
2. `currentSeat` 显示新岗位。
3. 默认机器人、默认协作空间、继承结果与策略一致。

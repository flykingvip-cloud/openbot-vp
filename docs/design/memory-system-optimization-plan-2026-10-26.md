## 0. 目标、范围与非目标（按 D1–D7 重写）

### 0.1 目标（仅依据已核实问题 + 审核修订方向）

1. **补证据与隔离方案**：把复查中的可复现证据、隔离复制/启动断言写清，作为一切修复的前置。
2. **先建立 O8 修改前基线**：用可重复合成测试集固化修改前结果，再谈修复对比。
3. **可观测性**：按后端定义只读健康探针（O1）；审计按配置来源/权威库/作用域/是否预期有数据区分空 Markdown 语义（O2）；不以全库 atoms>0 证明单数字人健康。
4. **ACL 测试契约**（O3）：对齐 `ensureMemorySubjectBinding`；不把测试失败当成 ACL 整体崩溃。
5. **隔离诊断优先**：O4（subject binding）/ O5（遗忘）先在隔离环境复现/验证；**仅在确认缺陷后**才进入修复设计与实施批准。
6. **指标诚实**：atom `reuseCount` 标明不可用于效果评估并定义分层新指标（D1），**本轮不接通自增、不废弃字段、不改排序权重**；学习相关性过滤先离线评估，默认行为不变（D2）。

- 不重写整个记忆系统。

## 3. 分步执行动作、验收、测试、风险与回退

### Step 0 — 证据与隔离方案（前置，文档/脚手架）

- **动作**：固化复查报告中的命令/SQL/行号；编写隔离运行手册（见 §3 O4 隔离细则，O5 共用）。
- **验收**：他人可按文档复现只读计数与 M03 误报；隔离启动前断言清单可执行。
- **本阶段**：仅文档；不改业务代码。

### Step 1 — O8 修改前基线（先于修复）

- **动作**：
  1. 建立**可重复合成测试集**（场景清单与样本数**分开**定义，见 §5）。
  2. 在隔离环境、**当前未改代码**下跑通并保存修改前结果 → `docs/design/evidence/memory-e2e-baseline-pre-YYYY-MM-DD.json`（无正文，仅 ID/命中布尔/延迟/评分）。
  3. 若效果测试有模型参与：记录**模型名、提示词版本、重复次数、评分规则**。
  4. 修复实施后另存 `…-post-…json` 做对比；**禁止**「先改再采」充当基线。
- **验收**：修改前文件已入库（或证据目录就绪）；场景覆盖矩阵完整；样本数达标定义与场景定义分离。
- **风险**：把「7 天线上」当成基线 → 不可重复；本方案改为合成集优先。
- **回退**：无代码回退；保留基线文件不可覆写（新文件对比）。

### Step 2 — O1 按后端定义的只读健康探针

- **动作（设计约束）**：
  - **禁止**只改 `backend` 字符串却仍让旧探针去检查错误表/错误 sqlite 路径。
  - 按 backend 分支选择只读探针：`builtin` / `qmd` / `cogniweave` **语义不得混用**（QMD 不能直接套 builtin 检查）。
  - 明确区分：
    - `probeExecution`: ok | error（探针本身是否跑完）
    - `backendHealth`: healthy | degraded | unhealthy | **unknown**
  - 覆盖：实际后端、存储路径/指纹、作用域、可读性、新鲜度。
  - **没有检索证据时不得报告检索正常**；检索项保持 `unknown` 或省略。
- **验收**：本机 `memory.backend=cogniweave` 时报告 backend=cogniweave；未知项为 unknown；单测覆盖三后端。
- **测试**：扩展 `doctor-memory-health.test.ts` / health-probe；禁止改生产配置。
- **风险**：UI 写死 builtin 文案；低。
- **回退**：**不得**「恢复硬编码 builtin」作为回退（会重新引入已知误报）。允许：feature flag 回到「legacy probe + 显式 `backendHealth=unknown` + 警告」或整 PR 回滚到引入前的绿色检查点，且回归测试须继续失败于「谎报 builtin 为健康」类断言。

### Step 3 — O2 审计空 Markdown 四态（非一律降为信息级）

- **动作**：综合以下信号分类，**不能**简单把所有空 Markdown 降为信息级；**不能**用全库 `atoms>0` 证明某个数字人健康：

| 分类         | 条件（示意）                                                                  | 建议级别                    |
| ------------ | ----------------------------------------------------------------------------- | --------------------------- |
| 新建空数字人 | 配置来源完整；权威库可读；**该作用域** atoms/events=0；创建时间新且预期无数据 | 信息                        |
| 来源缺失     | 配置期望 Markdown/session 源，但路径/绑定缺失                                 | 警告/P1                     |
| 诊断不足     | 权威库不可读、backend 未知、作用域无法解析                                    | 警告（unknown），要求补诊断 |
| 确定异常     | 配置/权威库可读；作用域内应有数据却为 0，或与同作用域写入日志矛盾             | 错误/P0                     |

- 恢复建议按后端分支（D5）：CogniWeave **不得**无条件 `force reindex`；builtin/QMD 各按自身条件给建议，不做一刀切删除。
- **验收**：elledecke 类 agent 不再被「唯一 P0=empty-workspace」误伤；输出含 backend、作用域计数、分类标签。
- **测试**：fixture / `--json` golden。
- **回退**：`--legacy-markdown-heuristics` 仅作对比，不得作为默认。

### Step 5 — O4 subject binding：隔离诊断 →（确认后）修复

#### 5.1 隔离要求（强制；O5 共用）

- **复制方式**：使用 SQLite **在线备份**（如 `VACUUM INTO` / `sqlite3.backup` API），**禁止**在可能有 WAL 时直接 `cp` 主库文件（会遗漏 `-wal` 内容导致不一致）。
- **隔离根**：临时目录下重建完整树；启动前**断言**所有写路径均落在临时根下。
- **须隔离的平面**（列清方法）：

| 平面              | 隔离方法                                                                |
| ----------------- | ----------------------------------------------------------------------- |
| 配置              | 临时 `openbot.json` / 环境注入；勿读真实 `~/.openbot/openbot.json` 写回 |
| state             | `OPENBOT_STATE_DIR`（或等价）→ 临时 state                               |
| data / Data Space | `OPENBOT_DATA_ROOT` → 临时 data；权威库为备份副本                       |
| workspace         | agent workspace 指向临时树                                              |
| session           | sessions 目录指向临时树                                                 |
| tenant            | `OPENBOT_TENANTS_ROOT` → 临时 tenants                                   |
| 协作目录          | collaboration/groups 根指向临时树                                       |
| 网络出口          | 默认阻断或 mock 云同步；`cloudSync.enabled=false`；不持真实云凭证       |

- **仅设部分环境变量不能证明**不会访问真实库：启动前用探针列出解析后的绝对路径，断言前缀 ∈ 临时根；失败则拒绝启动。
- **优先合成数据**；确需真实样本时仅用备份副本只读/受控写入。

#### 5.2 诊断

- 在隔离副本调用 `listMemoryCenterAtoms`（或等价），观察 `cogniweave_memory_subject_bindings` 是否增量、越权是否为空。
- **验收（诊断）**：有明确「缺陷成立/不成立」记录。

#### 5.3 修复（仅确认缺陷且审核批准后）

- ensureBinding 持久化须**验证主体归属**；不得默认「bindings 只增不害」。
- **回退**：停止调用；若需撤销错误绑定，走显式 unbound/审计删除，而非假设无害。

### Step 6 — O5 遗忘流程：先复现，再设计可恢复流程

- **动作顺序（强制）**：
  1. 在隔离环境复现现有 `data.memory.forget` 入口的实际问题（文件删后检索是否仍命中、lifecycle 表是否有行）。
  2. **仅当确认缺陷**后，设计可恢复、幂等的操作流程，定义：定位 → 授权 → 执行 → 部分失败 → 重试 → 完成状态 → **删除后召回检查**。
  3. **不得**默认 purge；**不得**以关闭旗标作为数据回退（关旗标不能恢复已删数据）。
  4. **不得**预先批准 best-effort「先删文件再 lifecycle」方案（D4）。
- **验收（诊断）**：复现报告含命令、前后检索布尔、生命周期行数。
- **验收（修复，若批准）**：隔离下删除后召回=0；部分失败可补偿；完成态可查询。
- **回退**：保留备份副本；回滚代码到绿色检查点；数据恢复走备份/备份导入，不靠关旗标。

### Step 7 — O6 / O7（非首批；决策状态见 §7）

- O6：仅文档/仪表盘标明 atom `reuseCount` 不可用于效果评估；定义分层指标（写入成功 / 召回命中 / 提示词构造 / 请求发送 / 正确采用）；**不**改排序权重。
- O7：离线对比「相关 vs 无关」经验筛选结果；默认线上行为不变，再决定是否改默认。

## 4. 观测指标定义（不得混用）

| 指标名                  | 定义                                                                                          | 非定义（禁止混用）       |
| ----------------------- | --------------------------------------------------------------------------------------------- | ------------------------ |
| 写入成功                | write_operation 落账且 `result.status=COMPLETED`（或等价 journal 成功）                       | ≠ 可被召回               |
| 索引新鲜度              | 源文件 checksum/mtime 与 indexed doc/snapshot 一致的比例；或 `lastSyncAt` 滞后                | ≠ 回答正确               |
| 召回命中                | 检索 API 返回含目标 atom/evidence/path（隔离集标注）                                          | ≠ 进入提示词             |
| 提示词构造 / 提示词注入 | 目标记忆片段出现在**已组装、待发送**的 system/tool 上下文（对应学习侧 `recordLearningReuse`） | ≠ 请求已发送；≠ 模型采用 |
| 请求发送计数            | 在确认出站模型请求（或等价 SDK send）处分项计数                                               | ≠ 提示词构造             |
| 回答正确采用            | 最终用户可见回答使用了该事实且与金标一致（人工或裁判模型+规则）                               | ≠ 仅召回命中             |
| 删除后召回              | forget 流程**完成态**后，同查询对目标 locator/atom 命中数为 0                                 | ≠ 文件已 unlink          |

## 建议顺序

依赖关系来自现有旗标，不是新的阶段设计。

1. **G8** 先写死：生产执行器仍是 Legacy Primary/Supplement。后续条目都不得绕开它直接切流。
2. **G7** Namespace 生产切流。宪法要求事实根先迁到租户命名空间。Floor 或 Episode 的生产写入在 N2 通过之前不能打开。
3. **G2** 在旗标后做 Episode Runtime 与单 Beat Controller。多 Beat 不在这一步。
4. **G3** Facilitator 挂在该 Beat 的观察点上，而不是挂在协调者的发言槽上。
5. **G1** 只有影子对比不再改写参与者、且单 Beat 门禁单独签署之后，才讨论 Floor 成为编排路径。本清单的 G1 成功标准不是把 `protocol` 设为 `floor`。

## G8 Legacy 仍是生产主路径

生产群消息的编排执行器是 Primary/Supplement 回合机。Floor 与 Episode Store 默认不接管。

入口文件：

- `src/gateway/server-methods/chat.ts`（调用 `executeCollaborationRound`）
- `src/gateway/collaboration-dispatch/round-runtime.ts`
- `src/gateway/collaboration-dispatch/round-state.ts`
- `src/gateway/collaboration-dispatch/decision-engine.ts`
- `src/gateway/collaboration-dispatch/legacy-policy-view.ts`
- `src/gateway/collaboration-dispatch/policy-lane-dispatch.ts`（默认 `legacy`）

非目标：

- 不删除 Primary/Supplement，也不在本阶段用 Floor 名单替换 `decideParticipants` 的结果。
- 不把 `collaboration.floor.protocol` 设为 `floor`。
- 不把能力车道改成 `effective`。

成功标准：

- 默认配置下，群回合仍只由 `executeCollaborationRound` 推进 `PRIMARY_*` 与 `SUPPLEMENT_*`。
- 文档与代码注释不再写「全仓无 FloorBid / Episode」。
- PolicyV1 继续只作为 EffectivePolicy 的兼容视图被这条路径读取。

## G7 Namespace 生产切流

库内实现已经能解析 `<groupLocator>/runtime`。默认事实路径仍是 legacy。切流是独立门禁，不是随手打开布尔值。

入口文件：

- `src/gateway/collaboration-dispatch/runtime-namespace.ts`
- `src/gateway/collaboration-dispatch/runtime-namespace-migration.ts`
- `scripts/migrate-collab-runtime-namespace.ts`
- `docs/design/collab-floor-p0-0a-runtime-namespace-cutover-2026-10-05.md`

非目标：

- 本清单不执行 `--apply`，不把 `collaboration.runtimeNamespace` 设为 true。
- 不把 operating-state、behavior buffer 一并迁进 `<ns>`。手册写明它们留在现有群存储。
- 不借切流之机打开 Floor live 或 Handoff 默认值。

成功标准：

- N2 前置全部满足：只读生产扫描附在切流单上，隔离项为零或逐条签署，校验和全匹配，写冻结窗口生效，拷贝演练与 `--reverse` 通过。
- 旗标打开后，托管企业缺少可信租户时失败关闭，不得退回主机 legacy 根。
- 旗标仍关闭时，`resolveCollaborationRuntimeFactPaths` 继续返回 legacy 路径。

## G2 Episode Runtime 与 Beat Controller

状态机和 Store 已在，默认不运行。缺的是单拍运行时：谁创建 Episode、谁推进状态、谁在一拍结束时停住。

入口文件：

- `src/gateway/collaboration-dispatch/episode-state.ts`
- `src/gateway/collaboration-dispatch/episode-state-machine.ts`
- `src/gateway/collaboration-dispatch/episode-store.ts`
- `src/gateway/collaboration-dispatch/collaboration-event-key.ts`（`episodeIdForClientRun`、`beatIdForEpisode`）
- 现执行器对照：`round-runtime.ts` 的 `executeCollaborationRound` 与 `BeatExecutionInput`

非目标：

- 不做多 Beat 循环。
- 不把 `collaboration.episodeStore` 在未过 P1-B① 时默认打开。
- 不把 `BeatExecutionInput` 改名为控制器来宣称完成。
- 不生产切流 Floor 协议。

成功标准：

- 存在一个旗标后的单拍运行时：一回合最多一个 Beat，状态沿现有转移表前进，Store 与 round 目录互不读写（现有 `episode-boundary.test.ts` 的边界保持）。
- 旗标关闭时 `chat.ts` 行为与现在相同，仍走 G8。
- `recoverIncompleteEpisodes` 只在 Store 旗标打开时处理非终态，默认仍是空操作。

## G3 Facilitator 控制平面

协调者不是默认发言人。这条已经由决策引擎的可选 wrap 守住。缺的是独立于发言槽的控制动作。

入口文件：

- `src/gateway/collaboration-dispatch/episode-state.ts`（`FACILITATOR_OBSERVE`、`stop_loop`）
- `src/gateway/collaboration-dispatch/episode-decision-record.ts`（`facilitator` 字段与三种 gate 结果）
- 对照，不是执行器：`decision-engine.ts` 里的协调者 wrap

非目标：

- 不实现旧文里尚未存在于源码的 `CHALLENGE`、`REQUEST_EVIDENCE` 字符串，除非后续契约明确加入现有 EDR 结果枚举。本清单不扩展该枚举。
- 不让 Facilitator 在无 @ 时独占回合。
- 不生产切流 Floor 协议，也不把 Growth 读进这里。

成功标准：

- 控制动作挂在 G2 的单 Beat 观察点上，结果写入已有的 `facilitator[]` 形状（`authorized`、`denied`、`route_to_task_governance`）。
- 动作不改变 G8 的参与者名单，直到 G1 的单独门禁允许。
- 无 @ 的协调者仍然只是可选 wrap，或保持沉默。

## G1 Floor 尚未成为 live 编排路径

L0、L1、Admission、L2 Bid 与 shadow 附件已经在影子路径上。它们今天不是谁可以发言的权威。

入口文件：

- `src/gateway/collaboration-dispatch/router-l0.ts`
- `src/gateway/collaboration-dispatch/router-l1.ts`
- `src/gateway/collaboration-dispatch/admission.ts`
- `src/gateway/collaboration-dispatch/floor-bid.ts`
- `src/gateway/collaboration-dispatch/floor-shadow-plan.ts`
- `src/gateway/collaboration-dispatch/floor-shadow.ts`
- `src/gateway/collaboration-dispatch/shadow-stage-flag.ts`
- 挂钩点：`decision-engine.ts` 的 `attachFloorShadow`；`round-runtime.ts` 里仅在影子旗标下启动的 bid

非目标：

- 不把 `collaboration.floor.protocol` 设为 `floor`。该值保持未接线。
- 不让 Bid 的 `drivesProductionDecision` 变为 true。
- 不在 G7 切流与 G2 单 Beat 完成前，把影子 admitted 名单提升为生产名单。
- 不新增策略字段。

代码门禁（默认关闭，本项仍开放）：

- `floor-live-cutover.ts` 的 `FLOOR_LIVE_CUTOVER_DEFAULT` 为 false。生产发言人仍是 G8。
- `protocol=floor`、`shadowStage`、`episodeStore`、`runtimeNamespace`、`handoffContract`，或单独的 `drivesProductionDecision`，都不能签署切流。还要四段回执同时为真，并且模块默认被打开。当前默认是关的，所以回执齐全也拒绝把 Floor 名单写成生产发言人。
- 影子 A/B 仍只挂附件和对比记录。`protocol` 仍不是 `floor`。单 Beat 切流回执没有签署。在那之前，本项保持开放。

成功标准：

- 默认配置下 `attachFloorShadow` 返回原决策对象，`isCollabFloorShadowEnabled` 为 false。
- 显式打开 A 或 B 时，附件与 jsonl 可以对比 legacy 与 floor 名单，参与者与可见回复仍来自 G8。
- 任何「Floor 已 live」的声明都要同时指出 `protocol` 仍不是 `floor`，以及 G2 单 Beat 门禁的签署记录。在那之前，本项保持开放。
- 把 Floor admitted 名单提升为生产发言人的入口会失败关闭。单独一个布尔值签不了这个门禁。

## 1. 冻结宪法

这些规则只锁定语义。实施可以补齐缺失的执行器，不得改义，也不得用新的 tip-prompt 或新的策略字段绕开。

| #   | 规则                       | 冻结含义                                                                                                                         |
| --- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Policy 不等于 prompt       | L1/L2 经 Policy Compiler 得到带 provenance 的 EffectivePolicy。Guidance 可以进提示词。数值、准入、闸门、账本不得改由提示词承担。 |
| R2  | Round 不等于 Task          | Round / Episode 管这一轮怎么沟通。Task / Handoff 管责任怎么迁移。Governance Gate 管什么最终生效。三套状态机不得互相代替。        |
| R3  | Bid 不等于授权             | Floor Bid 与认领只表达意向。获权必须经过 Policy、Admission、Floor，以及资源或治理闸。`selfAssessment` 不能单独过线。             |
| R4  | Coordinator 不等于 Speaker | 协调者是 Facilitator，不是默认发言人。无 @ 时不得独占回合。收口是可选 wrap。                                                     |
| R5  | Growth 不等于热路径        | 绩效只进异步 Learning。单轮 Admission、选人、Badge 不得读取 Growth。                                                             |
| R6  | Handoff 等于合同           | 责任迁移顺序是 Proposed、ReceiverAccepted、Approved，然后才改 TaskResponsibility 并写 Ledger。禁止先改 owner 再补事件。          |
| R7  | Ledger 等于执行真相        | 「已经完成」必须有执行事实。决策记录（EDR/PDR）解释为什么这样选，不代替执行账。                                                  |
| R8  | Floor 顺序                 | Shadow，然后单 Beat，然后多 Beat。影子结果不得改写生产参与者。`protocol=floor` 在单 Beat 门禁通过前保持未接线。                  |
| R9  | Legacy 等于兼容执行器      | 生产编排仍由 Primary/Supplement 回合机执行。它是兼容执行器，不是 Floor 宪法本身。                                                |
| R10 | Namespace 切流优先         | 租户运行时命名空间先完成生产切流，再把新的 Episode / Floor 事实写成生产路径。实现存在不等于已经切流。                            |

质量是横切约束，不是再加一层垂直平面。主动参与不等于 Claim。`responseMode` 的目标地位是意图信号，不是编排权威。本文不新增 `proactiveBots2` 或 `executionBlocked` 之类字段。

## 2. 状态词

| 状态        | 含义                                                                 |
| ----------- | -------------------------------------------------------------------- |
| LIVE        | 当前群聊或任务主路径会执行，且默认配置就会走到                       |
| SHADOW      | 代码会在显式影子旗标下计算或记录，且不得改写生产决策。默认旗标是关的 |
| FLAG-OFF    | 实现与测试都在，默认配置不执行、不落盘                               |
| DESIGN-ONLY | main 上没有对应执行器。至多有类型名、状态名或文档                    |

## 4. 生产路径一句话

默认配置下，群消息进入 `chat.ts`，构造 RuntimeAuthority，由 `decideParticipants` 选出 Primary/Supplement，再经 `runSingleBeatEpisodeAroundRound`（`episodeStore` 默认关 → 透明透传）调用 `executeCollaborationRound`（G8 Legacy Primary/Supplement）。Floor L0/L1/L2、Episode Store、Facilitator、EDR/PDR、HandoffContract、namespace 事实根都已有代码，默认全部不接管发言人名单。P0 G1 的切流门禁默认关闭：`FLOOR_LIVE_CUTOVER_DEFAULT=false`，`collaboration.floor.protocol` 仍不是 live 编排路径。

## 5. 与 Owner 审阅不一致或需要写细的地方

审阅的方向与代码一致。下面几条若写成「已经做到」就会过头，矩阵以上表为准。

1. Beat 身份辅助与 G2 单拍外壳均已存在：`episode-single-beat-runtime.ts` 在 `episodeStore` 打开时驱动一拍并拒绝 apply `next_beat`。P5 抬升闸门（`collaboration.episode.maxBeats`，默认 1）可写 EffectivePolicy / Facilitator 观察授权，仍无多拍 Controller。不得把「闸门可抬」写成「多拍已切流」。
2. Facilitator 模块 `facilitator-control.ts`（G3）已接线观察点；`CHALLENGE` 与 `REQUEST_EVIDENCE` 具名动作仍不在 `src/` 中。已有的是 `stop_loop` / `route_to_task_governance` 与 EDR 上三种 gate 结果。
3. `busyAgentIds` 只是 `blockedAgentIds` 的投影，排除原因字符串仍是 `blocked`。busy 与 executionBlocked 的拆分尚未落地。
4. Policy Compiler 在热路径上运行，但五条能力车道默认 legacy，持久化快照默认关闭。不能把 Compiler LIVE 写成「EffectivePolicy 已是全部消费权威」。
5. 质量并不只有影子分类器。冗余抑制和客套跳过已经在 `chat.ts` 热路径上。统一 Quality Gate 仍然缺失。
6. Constitution §3.4 曾将 Episode Runtime / Facilitator 标为 DESIGN-ONLY；与 G2/G3 代码不符。P3 inventory 已纠为 FLAG-OFF wired。见 [`collab-p3-status-inventory-2026-10-12.md`](../collab-p3-status-inventory-2026-10-12.md)。

## 1. 已批准产品契约（O4 收敛）

### 1.1 两种状态视图

| 视图               | 语义                             | 默认 |
| ------------------ | -------------------------------- | ---- |
| **已确认**         | 仅 `active`                      | 是   |
| **候选（待确认）** | 仅 `tentative`，行内标「待确认」 | 否   |

不在本契约内默认提供「全部可管理 / conflicted / deprecated / tombstoned」产品视图（若将来需要，另批只读诊断工具，不混入本契约）。

### 1.2 状态精确过滤

- 列表必须以**精确状态**过滤（推荐参数名 `statusView: "active" | "tentative"`，名称实施时再定）。
- **禁止**用模糊「多状态 OR」或默默抬高 `includeTentative` 全局默认来凑列表内容。
- 缺省行为保持今日实现：`includeTentative` 缺省 false → 仅 active。
- DTO 已含 `status`；实现批准后由 UI 标注，不得靠改库状态「造可见性」。

### 1.3 ACL

- 继续 `assertMemoryCenterAgentAccess` + subject binding fail-closed。
- **候选列表与候选计数**必须与已确认列表**同一 ACL**；禁止「未绑定也可看 tentative」。
- enterprise admin 仍不得经由 Memory Center 读员工私有记忆。
- 跨租户 / 错主体 / 未绑定 → 空列表（与 O3 矩阵一致）。

### 1.4 读取副作用边界

| 动作              | 允许                         | 禁止                                    |
| ----------------- | ---------------------------- | --------------------------------------- |
| 打开「候选」视图  | 只读列出 tentative           | 写库、晋升 active、自动绑主体           |
| 展示候选数量      | 经同等 ACL 过滤后的计数      | 为非空列表批量晋升或放宽 ACL            |
| 空态文案          | 区分「无已确认」vs「有候选」 | 暗示候选即已确认记忆                    |
| 详情展示 `status` | 只读                         | 在原子详情增加删除/忘记按钮（非本契约） |

**展示候选 ≠ 提升状态；不改变正常召回策略；不因打开筛选而写库。**

### 1.5 非目标（契约明确不做）

- 改默认召回 / `includeTentative` 全局默认。
- 批量确认晋升、一键全部 active。
- 遗忘 lifecycle 串联、purge、迁库。
- 在未获实现批准前改任何产品代码。

## 2. 现有契约证据（摘要，仍有效）

1. **无**更早的用户可见明文规定「记忆中心只展示 active」或「必须默认展示 tentative」；本文件 §1 现为**已批准**成文契约。
2. 实现上 `listMemoryCenterAtoms` → `queryAtoms` 默认不含 tentative（与检索生命周期门闩一致）。
3. DTO 已含 `status`；UI 不展示、无筛选（**实现仍待批准**）。
4. 空态「暂无可管理的记忆。」在仅有 tentative 时会掩盖「有候选待确认」。
5. CogniWeave：tentative 可进**检索候选集**（降权）——注入语义 ≠ Memory Center 列表政策；二者可分离。

## 3. 拟改界面与接口（设计级 — **实现仍待批准，本轮不实施**）

### 3.1 UI（待实现批准）

- Memory Center「记忆要点」增加筛选：`已确认`（默认）/ `候选（待确认）`。

| ---- | ---------------------------------------------------------------------- |

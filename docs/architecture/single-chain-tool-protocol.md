## 1. 一句话目标

**工具执行只接受**：供应商原生结构化工具调用，经**可信适配层**转换成内部规范调用后，再走现有工具策略、参数校验与授权流程。

**不得**从 assistant **正文**构造可执行调用（禁止 promote / 正文升格）。

正文中的协议包装（DSML、约定范围内的 XML tool markup 等）视为**协议违约信号**：检测、剥离、记事件、在适用情况下**显式终止回合**；学习与进化只改进同一执行契约，**不开第二条业务执行链**。

多种供应商协议（Anthropic Messages、OpenAI Responses 等）经适配进入同一内部规范 = **仍是一条业务执行链**，不是多链路。

---

## 2. 核心契约（修订后）

> 工具执行只接受供应商原生结构化工具调用经可信适配层转换形成的内部规范调用，并继续经过现有工具策略、参数校验和授权流程。不得从 assistant 正文构造可执行调用。

补充约束：

1. **提示规则只是辅助**；可信边界必须由**代码**保证（卸 promote / repair + 终止状态 + 检测不执行）。
2. 内部规范调用形态以现有 runner 识别为准（如 `toolCall` / `toolUse` / `functionCall`），由既有适配层产出；**本次 PR 不扩张/重构**工具名规范化与授权机制（命名空间后缀、大小写匹配等另行评估）。
3. 文件头边界声明（`model-output-boundary.ts`）与 runner 行为必须一致。

## 3. 混合消息与副作用边界（契约项 2）

当前 promote 在已有结构化调用时会直接返回（`attempt.ts` ≈569 附近）— 混合消息是**已有明确边界**，方案必须写清，不能遗漏。

| 情形 | 规则 |
| --- | --- |
| **只有违规正文** | 不生成任何工具调用；记录违约；返回明确失败；**结束当前执行推进**（见 §4 终止状态） |
| **合法原生调用 + 违规正文共存** | 正文剥离并记违约事件；**合法原生调用**继续经正常校验与授权执行；正文**不得新增**任何调用 |
| **协议教学 / 引用 / 代码示例** | 仅作文本处理，**永不执行**；是否向用户展示由明确内容规则决定（默认：保留现有 fenced code 中 DSML 示例边界，见 §5；若产品要改须单独说明） |

### 验收措辞（修正）

- **错误（旧）**：「任意 DSML 正文回合：零 tool 副作用」— 与「有原生调用即执行」冲突。  
- **正确（新）**：
  - **正文协议不得新增任何工具调用**；
  - **纯正文违约**仅保证**该次违规模型响应**不引起**新的**工具副作用（不否认同一 run 此前已完成的工具操作）；详见 §7.3.C。

## 4. 显式终止与续跑隔离（契约项 3）

删除 `protocol-repair` 后，runner 仍有进度停滞、误确认、工具后空回复等**自动续跑**逻辑（`attempt.ts` ≈2537）。这些会再次发送隐藏消息并触发模型。

### 要求

1. 为**纯正文违约**设置明确的回合终止原因，例如 `protocol_violation`（名称以实现为准，语义固定）。
2. 现有续跑逻辑必须**显式跳过**该终止状态；**不能**依赖失败文案碰巧不匹配续跑条件。
3. 保留正常续跑能力；但必须用测试证明：进入该终止状态后，**不会**经其他续跑入口间接恢复执行或隐藏修复。

## 5. 检测与执行分离；协议与示例边界（契约项 4）

### 5.1 分离原则

- **检测能力**：识别协议包装 / 残缺形式，产出检测结果（种类、名字、位置等）。
- **执行能力**：仅消费适配层产出的内部规范调用。
- 禁止「检测结果 → 构造可执行调用」的任何回接；卸 wrapper 不够，结构上要让正文执行**接不回去**。

### 5.2 协议覆盖（现状缺口）

- `applyUserVisibleOutputGate` 当前主要覆盖 DSML 及部分未闭合 token；`ProtocolKind` 列出其它种类**不等于**已完整实现。
- MiniMax XML 另由 `pi-embedded-utils.ts` ≈20 处理，且要求含 `minimax:tool_call` 才清理；方案原「XML invoke 统一违约」**尚未成立**，须在实现中**统一定义**识别范围。

### 5.3 识别范围建议

- 统一定义需要识别的协议包装及**残缺形式**。
- **避免**把普通单词 `invoke` 或任意 XML 判成违约。
- **默认保留**现有 fenced code 中 DSML 示例边界（`model-output-boundary.test.ts` ≈177）；若产品要改变展示策略，须单独产品说明，不混进「不执行」契约。

### 5.4 `recoveredCalls` 收窄

若观测只需名字：将检测结果收窄为**种类、名字、位置（及必要元数据）**，避免继续解析并携带**完整可执行参数**进入学习账本或宽事件。

## 6. 违约事件持久化（契约项 5）— **列入 P0**

### 6.1 唯一记录位置

- 在 **runner 模型响应边界**统一形成一条违约事实。
- **展示层只消费结果**；禁止多个输出门禁各自写账本（避免重复计数）。
- 现状参考：`pi-embedded-subscribe.handlers.messages.ts` ≈306 已有 `protocol_text_detected`（种类、恢复调用数、是否残缺），但**不能**证明已满足下方持久账本要求，且缺 model / 允许工具集等。

### 6.2 P0 最小字段

| 字段 | 说明 |
| --- | --- |
| `eventId`、时间、`schemaVersion` | 去重与演进 |
| `runId`、attempt/turn 标识 | 回合定位 |
| `sessionId`、`agentId` | 会话定位 |
| `provider`、`model` | 分模型分析 |
| 协议种类及违约分类 | 与检测层一致 |
| **实际下发的工具允许集** | 须验证与最终请求一致；现有 `allowedToolNames`（≈1347）汇集服务端+客户端工具，实现时核对 |
| 检出的工具名（可空列表） | 不含完整可执行参数为宜 |
| 正文摘要哈希及长度 | 关联用；**不能单独**支持样本复盘 |
| 最终展示结果 | 如 `failure_copy` / `stripped_partial` |
| 是否触发工具执行 | 纯违约应为否；混合场景为「仅原生部分」 |
| 是否触发额外模型回合 | 纯违约应为否（无 repair / 无续跑绕过） |

### 6.3 落盘与失败策略

- **明确**：落盘位置、保留期、写入失败时的告警与处理策略。
- 哈希只能关联；若需分析原文，须引用**有权限控制与保留期**的取证来源，**不得**把完整工具参数默认复制进学习账本。

## 7. 失败展示与集成验收（契约项 6）

### 7.1 展示语义

- 现有清洗可能保留「我来检查」「我继续执行」等前缀（见 `model-output-boundary.test.ts` ≈162）。删除 promote 后若只展示这些文字，用户仍会误以为任务在执行。
- **纯正文违约**必须展示**明确失败**，建议可用：「本步工具调用未能执行，请重试。」
- 若此前步骤已有成功副作用，文案应限定为「**本步**」，避免暗示整个任务完全没有执行。
- `PROTOCOL_FAILURE_USER_TEXT` 可收窄为此语义；去掉 repair 二次失败语义。

### 7.2 集成验收矩阵（P0 必须）

须覆盖「模型响应 → 调用分派 → 展示 → 历史 → 下一轮」；**仅**检索不到 `promoteProtocol` / `protocol-repair` **不能**证明正文已无可执行路径。

| 场景 | 必须证明的结果 |
| --- | --- |
| 完整 / 残缺 / 未知工具名 / 无工具可用的纯正文协议 | 无正文生成的调用；明确终止；事件记录齐全 |
| 原生调用与违规正文混合 | 原生调用按正常规则处理；正文不新增执行；仍记录违约 |
| 跨 chunk、跨 text block、异常中止 | 不泄漏协议；不因分片漏记或重复计数 |
| 历史持久化与下一轮请求 | 违规原文未作为普通 assistant 历史回灌；合法工具调用与结果配对完整 |
| 通用自动续跑入口 | 纯正文违约后无隐藏修复、无续跑绕过 |
| 日志写入失败 | 执行边界仍成立（仍不执行正文）；观测丢失可告警 |

单元测试可重写（去掉「DSML promote 后 exec 成功」）；**必须**补充上述集成验证。

### 7.3 工程细化（PR 内落定，无须再架构审批）

以下三项属于实现设计细化。架构方向已定；实现 PR 必须具体落定，**不必**再开一轮架构审批。

#### A. 协议识别清单（落实 §5「约定范围」）

实现时将识别范围写成**封闭清单**，并配反例测试，避免启发式继续扩张。

| 类别 | 纳入（正例） | 排除（反例，不得判违约） |
| --- | --- | --- |
| DSML 完整包装 | 现有 gate 已识别的完整 DSML tool-call 块（含已知开闭标签形态） | 普通叙述中的单词 `invoke`、无关 XML/HTML |
| DSML 残缺形式 | 未闭合 / 截断的同族 token（与现有未闭合检测一致的部分） | 单个尖括号、普通代码比较符号 |
| MiniMax 等专用 XML | 仅当文本含约定标记（如现有 `minimax:tool_call` 路径）时纳入清理/检测 | 任意 `<tag>`、文档里的通用 XML 示例（非约定标记） |
| 代码围栏示例 | **不执行**；默认**不**因 fenced code 内 DSML 记「执行向」违约（保留现有示例边界）；若仅做防泄漏展示，按现有内容规则，不升格 | — |

PR 交付物：在代码旁或本附录增加「正例 / 残缺例 / 反例」测试表；新增识别种类必须改清单 + 测试，禁止静默加启发式。

#### B. 持久化契约（落实 §6）

| 项 | P0 落定要求 |
| --- | --- |
| **存储位置** | 选定唯一 sink（例如会话/run 旁路的结构化事件流或既有 diagnostics/evolution 管道中的一处）；PR 描述与代码注释写明路径 |
| **保留期** | sink=`$STATE_DIR/logs/protocol-violations.jsonl`（`OPENBOT_PROTOCOL_VIOLATION_LOG` 可覆盖）。**进程内不自转**；与同目录其他 `*.jsonl` 一并走既有 state-log 运维轮转（默认约 30 天）。代码注释与 `protocol-violation.ts` 文件头说明一致。 |
| **去重键（优先于随机 eventId）** | 建议：`runId + attemptOrTurnId + protocolKind + snippetHash`（或等价稳定组合）。同一模型响应若经多个回调（流式 chunk、订阅、展示）触发检测，**必须**用该键幂等写入或先查后写 |
| **eventId** | 可为去重键的确定性派生（推荐）或「首次写入时生成并缓存到该响应的 violation fact」；**禁止**每个回调各自 `randomUUID()` 导致重复记账 |
| **写入失败** | 执行边界仍成立（正文仍不执行）；发出告警/计数；不得为了「补写观测」而重放模型或打开 repair |

跨 chunk / 跨 text block：先在 runner 边界合成**一条** violation fact，再持久化；展示层只读该 fact，禁止门禁各自写账本。

#### C. 终止与副作用作用域（收紧 §3 / §4）

- **「纯正文违约零副作用」**仅指：**该次违规模型响应**不得引起**新的**工具执行。  
- **不否认**同一 `run` 中**此前**已经完成的工具操作（成功写文件等仍有效）。  
- 用户文案继续用「**本步**」，与此一致。  
- 事件中的执行状态须区分原生结构化调用的：
  - `requested`（适配层产出、进入策略前）
  - `rejected`（策略/校验/授权拒绝）
  - `executed`（实际产生工具副作用）
  - 正文协议路径不得出现「由正文产生的」`executed`；混合场景仅原生部分可进入上述状态。

验收措辞补充：证明「本响应无正文衍生执行」，而非「整个 run 从未执行过工具」。

## 10. 风险、回滚与故障处置

### 10.1 预期可见变化

以往靠 promote「歪打正着」跑通的纯正文协议回合，将变为**明确失败 + 终止**。这是收束契约的代价。

### 10.2 禁止与允许

- **原则保留**：禁止恢复 promote 作为产品能力。  
- **可操作故障处置**（补充）：
  - 暂停受影响模型的工具任务  
  - 切换至已验证模型  
  - 回滚**展示或观测实现**（不恢复正文执行）  
- 若**整个版本回滚**会重新引入 promote：必须视为与新契约**冲突**，不得把普通版本回滚默认当作安全处置；发布说明中写明。

## 11. 验收标准（修订总表）

1. **统一执行入口**：仅适配层内部规范调用可进入策略/校验/授权；正文不得新增调用。  
2. **纯正文违约**：无工具副作用；显式终止；无 repair；无续跑绕过。  
3. **混合消息**：原生部分正常执行；正文剥离 + 记事件；正文不新增调用。  
4. **可观测（P0）**：唯一写入点的持久事件字段齐全、可查询；写入失败可告警且执行边界仍成立。  
5. **历史净化**：违规原文不作为普通 assistant 历史回灌；合法 tool 配对完整。  
6. **无分叉回归**：生产路径无正文升格；集成矩阵通过（检索关键字仅为辅助，非充分条件）。  
7. **聚合报表（P1）**：有分母指标；不作为 P0 生产切换前提。

## 12. 专家结论与下一步

| 项 | 结论 |
| --- | --- |
| 架构方向 | **批准**（正文协议不执行；删除升格路径） |
| P0 开发 | **有条件批准** — 条件为本文 §2–§7 六项边界已写入方案并作为实现/验收依据（本文即修订稿） |
| 按旧文字直接生产改造 | **不批准** |
| 生产切换 | 测试 + 持久事件 + 发布门禁后**另行评审** |
